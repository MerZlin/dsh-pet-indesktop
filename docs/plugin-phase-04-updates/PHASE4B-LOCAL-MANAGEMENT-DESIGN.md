## 1. 目标、非目标与范围

唯一主验收链：**不安装也能启动 → 安装后入口出现 → 停用后不执行 → 卸载后文件与入口消失 → 重装恢复保留配置。**必须在真实独立冻结产物上验证，不能以新增文件、Worker 数量或模拟测试替代。

已确认两项规则：

- 同一应用数据根统一管理安装、整个功能包启停和卸载，影响使用该根的所有实例；视觉 profile、凭据和自动识屏开关仍按实例隔离。
- 版本占用时等待用户自然退出，不强制关闭桌宠或独立设置进程；明确显示占用者和待完成原因。

只接续 `official.screen-understanding`，沿用 Phase 4A 的两种无识屏验证 Core。原默认完整构建保持内置行为，不得显示成已支持物理卸载。本阶段不做 Setup 选装、远程下载、Workshop、第三方代码执行、便携模式、新用户数据迁移或清空个人数据按钮。不修改 Core 自动更新或演示 HTML，不自动提交、推送，不开子智能体。

用户随后授权的本地备份提交是本次检查点的单独例外，不授权后续自动提交或远程推送。当前版本独立视觉配置、自动识屏及托盘退出的用户手测未完成；以前手动识屏正常不替代当前版本验收，也不将未等待自动触发判作故障。

## 2. 单一安装状态与解析接口（4B-1）

沿用应用数据根，功能包布局固定为：

```text
plugins/official.screen-understanding/
  state.json
  versions/<version>/
  staging/
  transactions/
  locks/
```

`state.json` 是唯一安装状态权威：schema、递增 revision、已安装版本和完整摘要、active、previous、整包启用状态、待完成事务。事务日志仅用于恢复，租约仅用于占用证明，不能另行决定 active。不新增功能 `active.json`，不改变 Phase 1 角色资源格式。

配置、凭据、记忆、额度及聊天历史继续原路径。卸载后保留明确的未安装状态和偏好；孤立目录或 Core 更新不得让已卸载功能自行复活。Core 与独立设置进程经同一解析器得到已验证描述；扫描到目录不代表安装，更不能执行其中代码。

管理服务覆盖：查询状态/占用、预检目录或 ZIP、安装并启用、启停、卸载、升级、回滚、恢复。每次修改携带 operation ID 和预期 revision，同一功能仅一个修改事务。采用功能级内核锁，锁内重读、校验 revision、合并及原子保存；锁竞争与文件系统错误必须区分，均不得覆盖其他操作。解压/复制/哈希/签名工作进入后台任务，不阻塞 GUI，不在等待用户确认期间持锁。

损坏状态不是空状态：校验备份与事务记录，只恢复可以证明一致的状态；不能确定则禁止功能执行并提示修复，Core 仍启动。恢复不能覆盖更高 revision 的用户操作，不能从旧备份重新启用被用户卸载的功能。

**出口：**schema/字段约束、revision 冲突、真实多进程竞争、原子写中断及损坏拒绝测试通过；此时仍不加载任何功能代码。

### 2.1 本次切片：唯一状态与安全恢复（2026-09-30）

仅新增内部 `FeatureInstallStateStore`，不接生产启动、不做租约、解压/版本删除、通知或 UI。顺序为可收集的行为测试 red → 严格状态模型 → revision/锁 → 状态提交恢复 → 签名验证衔接。使用临时数据根，不读取实际安装和凭据。

- `read()` 返回不可变快照与分类诊断，不创建文件、不自动恢复。无管理痕迹才是首次未安装；缺状态且有备份、事务或版本残留必须诊断。
- `commit(change, expected_revision, operation_id)` 由服务增加 revision；同 ID 同请求返回原凭据，不复活旧状态；同 ID 异义或旧 revision 拒绝。布尔值不是整数，JSON 重复字段、非法版本/摘要、未来 schema 及未知字段均明确拒绝。
- `recover()` 只修复状态提交。有效较新状态优先；替换前中断保留旧状态，替换后补齐凭据。损坏/缺失仅在最新已提交快照可证明且无模糊后续提交时恢复；保留损坏原件；未来 schema 不重写。
- `resolve_verified()` 只返回已验证描述和 revision。锁外校验 manifest 原始字节 SHA-256、签名及完整包，锁内复核 revision；不 import factory、不启动 Worker，不是版本租约或长期执行许可。

状态只包含 `schema_version/feature_id/revision/versions/active/previous/enabled/pending_transaction`。`versions` 映射受限版本号到 manifest 原始字节的 SHA-256；它不能代替发布者签名。卸载标记持久化为空版本集合及未启用。版本目录固定推导，拒绝链接/重解析点和非正常文件。

功能级非阻塞内核锁区分锁忙与 I/O 故障。原子写使用同目录临时文件、flush、fsync、replace。`transactions` 保留带请求及前后状态摘要的 prepared/committed/aborted 记录用于恢复和幂等，不作为第二个 active。未提交候选绝不靠扫描版本目录启用；无法证明则停止恢复。记录暂不压缩或清理，达到有界上限明确拒绝而非丢弃证据。范围仅证明进程中断及注入 I/O 失败，不声称所有文件系统断电一致性。

| 子任务 | 验收 | 停止条件 |
|---|---|---|
| 1a 严格状态 | 首次、卸载、类型、重复字段、未来 schema、残留、路径 | 分类被吞成空状态 |
| 1b CAS/幂等/锁 | 真实两进程同 revision 仅一提交，锁忙和 I/O 区分，异常退出释放 | 覆盖别人或旧操作恢复旧值 |
| 1c 状态恢复 | 写入阶段中断、损坏、矛盾记录、最新卸载保护 | 未证明最新状态即激活 |
| 1d 信任解析 | 签名/摘要/兼容拒绝、验证时变更 revision 拒绝、不执行包代码 | 状态摘要被当作签名或执行授权 |
| 1e 验证留档 | 专项及相关回归、全量、Ruff、mypy、文档门；进程族三遍；有界耗时 | 新失败未分类或用旧结果代替 |

本步不提交或推送。回滚仅撤回新增内部服务和测试，不影响当前识屏。没有新增用户操作，安装和卸载仍待后续完成。

## 3. 跨进程占用与状态同步（4B-2）

### 3.1 版本租约

扩展已有进程内版本句柄，Core host、独立设置及 Worker 分别登记并持有自己的内核锁，记录进程身份、版本、用途。PID、时间戳或心跳过期均不是单独的安全删除依据。错误/不确定按仍占用处理。

获取租约和判定删除使用同一功能协调锁，关闭检查与新加载之间的竞争窗口。host 代码一旦进入解释器，即使停用、撤销入口或 import/factory 失败，仍保持该版本占用直到进程退出；不承诺 Python 热卸载。

Worker 独立持有租约，不能仅依赖父进程句柄。启动前登记保留占用；在导入功能代码前由子进程接管。只有确认接管或证明启动失败且无存活子进程后才释放保留记录。父进程在交接窗口死亡时，核对记录及操作系统进程身份；不能证明安全则显示占用待确认，不用超时猜测、不误杀外部进程。

### 3.2 同步、撤销与确认

监听状态目录，低频轮询补偿文件通知遗漏；通知只唤醒，revision 重读才是依据。新请求、旧 QAction/兼容入口执行、结果展示前均校验安装授权。

停用顺序：拒绝新任务 → 旧 generation 失效 → 撤销执行入口 → 停止所属 Worker → 各参与进程确认。界面区分“已请求停用”和“所有相关进程已确认停止”，未响应不能计成功。整包停用保留安全配置入口；仅关闭自动识屏不影响手动识屏。

进程确认与占用是运行证据，不是另一份安装状态。尚有旧 host 驻留时，新版本切换必须如实显示待退出，不能同时混用 host/设置/Worker 版本。正常 Worker 停止仍使用现有优雅关闭和超时兜底，只处理宿主自己的子进程。

**出口：**真实多 Core、设置及 Worker 占用，关闭一窗、异常退出、启动交接及旧动作/结果撤销均有过程级测试。

## 4. 本地安装、升级、卸载与恢复（4B-3）

### 4.1 安装及激活

```text
本地目录或 ZIP
→ 同盘 staging 复制/解压
→ 完整路径/大小/清单/摘要/签名/兼容性校验
→ 用户确认（无持锁）
→ 隔离子进程自检
→ 不可原地覆盖的版本目录
→ 提交权威状态
→ 宿主加载及确认
```

复用 Phase 4A 可信验证器，不将资源 ContentManager 变成代码安装器。拒绝路径穿越、链接、大小写冲突、重复 ZIP 条目、未登记文件及解压超限。复制后的完整包先验证，才允许 factory 或自检执行。自检用独立进程，不截图、不读取真实凭据、不请求模型，避免污染管理进程的永久 host 占用。

同版本同摘要安装幂等，同版本不同内容拒绝覆盖。自检通过不等于实际加载通过；注册失败必须报告并补偿。升级/回滚以整个版本为单位，不能混用 host/Worker；本阶段不引入数据 schema 迁移，不能证明降级兼容时拒绝降级。

### 4.2 恢复与失败补偿

每个关键写入、重命名、激活和删除前记录可恢复阶段：

- 状态提交前中断：旧 active 不变，不加载候选。
- 提交后加载失败：先禁止候选执行，有可用 previous 则安排恢复，否则保持故障且不启用。
- 失败 host 已加载：仍算占用，需要退出才能回滚时显示待重启，不宣称即时成功。
- 卸载中断：继续禁止执行并重试清理，绝不恢复成启用。
- 恢复重复运行必须幂等，过期操作不能覆盖更高 revision。

### 4.3 卸载与保留数据

先处理所有设置窗口未保存草稿；未处理则不开始破坏性卸载，列出窗口供用户保存或放弃后重试。取消保留草稿。接受卸载后阻止继续保存该功能草稿或执行新任务。

```text
禁止执行
→ 撤销菜单/设置/搜索/命令/订阅
→ 停止所属 Worker
→ 等待全部版本租约释放
→ 删除所有已安装版本代码和资源
→ 提交未安装状态
```

代码仍驻留时立即停功能，但显示“待退出相关进程后完成卸载”，列出实例、进程用途和版本。活着的管理进程可以继续清理；全部退出后，下次启动先恢复事务、再解析功能。文件还在就不能显示卸载完成。删除前再次验证目标属于安装根且不存在链接逃逸。

默认保留 profile、凭据、记忆、额度和聊天历史；无清空个人数据按钮。重装恢复保留配置，不自动再次从聊天配置迁移。

**出口：**目录/ZIP、安全拒绝、幂等安装、升级回滚、各关键阶段故障注入及重启恢复、多进程卸载/草稿保护均通过。
