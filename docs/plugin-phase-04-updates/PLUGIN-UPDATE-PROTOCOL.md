# Phase 4：资源与官方功能包的安装、卸载和更新合同

> 修订：2026-09-27。**本地官方可选交付是硬目标，远程分发按需。**以下区分已实现的角色资源事务与尚待落地的可执行功能包事务。

## 1. 两类包，不是一套任意代码加载器

| 对象 | 当前能力 | 后续要求 |
|---|---|---|
| 纯资源 content | Phase 1 `ContentManager`：目录/ZIP、路径及内容哈希、版本、staging、激活、自检、回滚 | 保留并复用，不执行代码；目前完整闭环主要是角色 |
| 官方功能包 | 当前官方插件/Worker 主要内置，不具备统一物理卸载闭环 | Phase 4A 设计受控加载及可信产物；4B 实现屏幕理解包和应用内管理 |

复用事务思想和经验证的工具，不表示直接把内容 manifest 的 entrypoint 打开。功能包可同时含主进程 UI/策略、Worker、资源和专属依赖；执行位置与交付位置不同。第三方代码执行不在本合同实施范围。

[屏幕理解最小设计](PHASE4A-SCREEN-PACKAGE-DESIGN.md)已确定暂用 ID `official.screen-understanding`、同版 host 与自包含 Worker、由 Core 信任锚验证官方发布者签名，以及应用数据根下的相对布局。安装描述的序列化/签名库选择、实际产物与 Phase 5A 便携适配仍待验证；不把设计写成已经支持的扩展名或复制即用路径。

## 2. 来源信任与执行前校验

- ZIP 禁绝对路径、`..`、符号链接和越界解压；限制包大小/解压膨胀和文件数量，先 staging 不覆盖当前版本。
- 校验 manifest、kind、API/Core/platform、声明路径、大小与 SHA-256；拒绝不兼容、缺依赖或冲突。
- **SHA-256 只证明内容一致，不证明发布者身份。**本地 ZIP 中带自己的哈希也不等于可信。
- 可执行官方包在任何代码加载、import 或自检前必须通过官方来源验证。屏幕理解采用发布者签名：`manifest.sig` 验证 manifest 原始字节，manifest 绑定 host/Worker/资源文件哈希；信任锚来自 Core，而非包自带公钥。采用成熟密码库，不自行实现算法，不等远程分发才强制；具体库与签名格式在实现前复核。
- 纯资源开发 `allow_unsigned` 不自动授予代码执行；开发豁免必须显式且与正式通道隔离。
- 安装权限说明与单次截图/网络/凭据授权分开，不能因安装 AI 聊天就取得截图权限。
- 验证失败保留安全的诊断和可重试包，不记录密钥、截图或完整敏感 payload。

## 3. 统一安装状态与生命周期

Setup、ZIP 导入、应用内管理、未来下载源共享同一安装事务和权威状态。Setup 不私自复制出“应用不知道”的第二套安装记录，发现一个目录也不等于授权执行。

```text
取得本地包 → staging
→ 路径/大小/哈希/可信来源/manifest/平台/Core/依赖校验
→ 用户确认权限与安装目标
→ 准备数据迁移备份和新版本（不覆盖用户数据）
→ 停止旧版本任务，协调实例并撤销旧贡献
→ 原子切换 active，保留 previous 与恢复记录
→ 受控启动自检与注册贡献
→ 成功提交安装状态；失败停止新版本并恢复 previous/数据/贡献
```

屏幕包以 `plugins/official.screen-understanding/state.json` 为唯一安装状态权威，记录 active/previous 与待完成事务；不要另建第二套独立 active 指针。host 和 Worker 原子选择同一版本，启动前持有版本租约，跨实例协调旧版本释放。版本目录不可混入配置/用户数据；配置仍在每实例插件命名空间，凭据留安全存储。Phase 1 角色资源既有 `active.json`/`previous.json` 不因此改动。

原子文件切换不意味着进程、UI、数据天然构成一个原子事务；必须有持久化阶段记录、崩溃恢复和补偿动作，避免半激活。安装同版本保持幂等；中断不破坏旧 active；schema 不兼容时拒绝盲目回滚。

依赖有明确所有者及引用关系。只能删除目标功能独占文件；共享依赖不得因卸载一个包损坏另一个包。共用视觉/模型能力采用窄接口或显式依赖，不能借“复用”将整套 AI 返回 Core。

## 4. UI 贡献与管理（本地必做）

最小扩展管理提供安装、状态/原因、启停、配置、卸载、版本和恢复入口，不依赖远程市场。菜单、设置、搜索、快捷键、命令、订阅按包 owner 管理，以 [API 生命周期合同](../plugin-phase-01-foundation/PLUGIN-API-CONTRACT.md) 为准。

安装后注册功能，停用不执行但可管理；打开设置不得触发网络、截图或长期任务。故障/不兼容显示原因，不能留下点击无反应的菜单。托盘与右键共用命令模型，保留排序偏好，不借本阶段重新设计整个菜单。

## 5. 停用、卸载与重装

```text
禁止新请求与安装状态变化
→ 通知所有占用实例，停止任务/Worker/功能 UI
→ 撤销 owner 的菜单/设置/搜索/命令/快捷键/订阅
→ 确认文件不被使用，再移除包版本与独占依赖
→ 更新权威状态；保留用户数据，允许后续重装恢复
```

- 文件锁或解释器模块驻留导致不能安全移除时，标记“待重启完成卸载”，重启后完成，不假装热卸载。
- 已卸载不允许自动 fallback；可执行功能没有“卸载后继续用 Core 内旧实现”的替代。屏幕包独立交付后，即使仍安装启用，Worker 有限重启耗尽也只暂停/重试/回滚，不转回 Core 执行截图或网络；当前内置 3B 的回滚代码本轮不改。
- 资源角色卸载可降级上一资源版本、Starter/legacy 或最小 Core fallback，这与功能授权完全不同。
- 卸载默认保留配置、会话等用户数据；删除个人数据要单独列影响并确认。凭据保持安全存储，不随包复制。
- 重装恢复保留偏好；缓存、日志、备份按明确保留策略处理，不混入包文件。迁移遵循 [迁移合同](../plugin-phase-01-foundation/PLUGIN-MIGRATION-v4-to-v5.md)。

## 6. Core 更新、目录和便携边界

现有 `pet/updater.py`、`pet/update_settings.py`、`update.json` 保持当前实现，本次只定义未来集成门：

- Core 更新不得删除用户 DLC 或重新装回已卸载功能；安装状态/用户选择独立保存。
- DLC 更新不得覆盖 Core 可执行文件和公共配置；Core 降级重新检查兼容，不兼容禁用并解释。
- 包版本、用户数据、cache/logs/staging 分离；仓库 bundled source 不是运行时写入目录。
- 显式便携模式可以将 DLC 与普通数据放在便携根下受管理的独立子目录，**同一父目录不代表能覆盖 Core 文件**。不能用“一律禁止 Core 目录下任何 DLC”否定便携模式。
- Setup 本地旁置包缺失时 Core 仍可安装启动；便携目录不可写应明确报错或由用户选择模式，不静默把写入目标改到另一处。
- 密钥不明文放入便携包；换机器可能需要重新授权。

## 7. 条件远程能力

未来 catalog 条目包含 ID、版本、Core/API 范围、平台、URL/镜像、大小、SHA-256、可信签名信息、依赖、覆盖/回滚策略与发布说明。

```text
catalog 筛选兼容版本 → 下载/多镜像重试 → 统一 staging 校验与安装事务
```

远程 catalog、自动检查、GitHub/CDN 与 Workshop adapter 按需实施；下载源只提供候选和下载，不另造加载和卸载规则。启用前测试签名失败、公钥轮换/撤销、离线、代理/VPN、下载中断与恢复。**管理 UI 和本地可执行包可信校验不是条件项。**

## 8. 验收矩阵与恢复

| 路径 | 必须验证 |
|---|---|
| 无包/离线 | Core 基础功能可用，产物无专属代码/依赖，无专属入口或后台进程 |
| 安装 | 目录/ZIP 同语义；信任/路径/哈希/依赖失败不执行代码或破坏 active |
| 启用/设置 | 入口正确、权限生效；仅打开设置不触发执行 |
| 停用/故障 | 无新任务；旧响应过期；有诊断；fallback 不绕授权 |
| 卸载/重装 | 撤销所有贡献，独占文件清理；多实例和占用明确处理；配置默认保留可恢复 |
| 升级/回滚 | 自检失败补偿；安装中断重试幂等；备份与 schema 恢复；Core 文件不动 |
| 构建/分发 | 最小 Core 清单、专属/共享依赖、包体与安装位置；Setup/ZIP/UI 状态一致 |

失败暂停新版本并恢复最后可用且仍授权的版本；用户主动卸载则保持卸载，不“自愈”成重新安装。远程失败不影响本地恢复。

## 9. 给使用者的效果说明

选装不是把开关藏起来，而是能不装这部分文件，也能从桌宠里卸载。识屏包将带自己的主进程 UI/策略和后台 Worker，Worker 通过本机 JSONL 管道受 Core 管理；包及用户数据分开。4A 已给出应用数据根下的功能包相对布局和 `state.json` 合同，包格式实现与便携适配仍待验证，当前不要把功能 ZIP 放进角色目录执行。安装后入口出现，卸载时停后台并移除入口/文件，默认保留偏好；第三方市场没做也不影响这套官方体验。
