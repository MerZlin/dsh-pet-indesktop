# Phase 6：第三方 SDK 与社区生态（条件阶段）

> 修订：2026-10-08。**条件启用，仅指第三方生态；不包括必须完成的官方功能选装。**
>
> **与Phase5A的边界（2026-10-08）**：R工程门已有最新默认全量/满CPU/冻结证据，真实Provider/系统操作与用户确认仍待验，Phase5A未关闭；见[报告§8](../PR-REPORT-PHASE5A-LOCAL-DISTRIBUTION-2026-10-07.md)。用户显式导入manifest/host/worker合同ZIP/目录是主动信任，Core通用owner/purpose端口不是官方factory特判，也不是Python沙箱/公开SDK。Phase6的在线目录、市场、作者审核、签名/撤销、兼容与故障流程仍条件启用，未因R端口实现而开放。

## 1. 与官方选装分开

Phase 4/5 必须提供可信官方包、应用内管理、Setup/ZIP 选装和卸载。即便永不开放社区生态，屏幕理解、AI 对话及其余官方领域也不能退回“只能内置开关”的交付。

本阶段是否向公共生态开放第三方作者，取决于真实需求、审核维护成本和安全/兼容能力；不把 Phase5A 的本地显式信任路径包装成公开 SDK，也不以开放任意 Python `entrypoint` 为目标。

## 2. 有条件推进顺序

1. 先提供 content DLC 格式文档、校验方式和示例，明确当前已支持的类型；内容包永不执行代码。
2. 有实际作者需求后评估 content SDK、作者元数据、兼容矩阵、API 弃用与迁移规范。
3. 只有 Worker 协议、最小权限、可信签名、配置/单次凭据边界、故障恢复与包级贡献合同稳定后，评估第三方 Worker SDK。
4. 社区 catalog、审核/下架、签名撤销、公钥轮换与故障报告流程具备维护能力后才开放来源。

官方可信 UI 可在主进程受控运行；Phase5A 的本地显式导入是“用户主动信任即可执行”的特殊产品路径，不等于第三方任意代码已经获得公开生态准入。QProcess 是故障隔离，不是 OS 安全沙箱；如需不可信代码，须另行设计威胁模型与执行限制，不沿用官方 allowlist 自称安全。

## 3. 进入和退出门

- 不引入 Core 离线启动依赖，不要求官方功能安装走第三方市场。
- 明确作者/包身份、capability 授权、签名与撤销、版本范围、兼容和弃用政策。
- 第三方贡献服从 [统一 UI/生命周期合同](../plugin-phase-01-foundation/PLUGIN-API-CONTRACT.md)，不能越权注册入口或读取其他包配置。
- 安装/卸载/回滚走 [统一事务](../plugin-phase-04-updates/PLUGIN-UPDATE-PROTOCOL.md)，资源安装器不得执行代码。
- 不承诺 Python 模块热卸载；占用时明确待重启。普通配置、数据和密钥区分，第三方授权另行审查。

任一门未满足则不开放该 SDK/来源，官方包继续正常发布与使用。

## 4. 给使用者的效果说明

这是“让其他作者也能发布扩展”的可选步骤，不是“你能不能安装官方识屏和聊天”的前提。官方包会先通过 Setup、本地导入和桌宠内卸载提供；Phase5A 本地包必须从扩展管理入口显式导入；Phase6 公共生态仍不能把包随便丢进角色目录就执行。安装文件仍由统一扩展管理放入版本目录、数据另外保留；Worker 通过受控本机协议连接 Core。具体第三方格式和隔离方式尚未承诺，社区生态没做不影响官方选装。

## 6. 外部基线评审后的开放闸门（2026-10-02）

第三方开放顺序保持：

```text
纯资源文档/示例
→ 本地资源制作与校验工具
→ 受控官方 Worker 包格式
→ 第三方外部 Worker 预览
→ 是否需要社区目录/平台分发
```

在每一层都必须明确数据目录、配置、缓存和密钥的包级作用域；第三方包不能读取其他包数据或 Core 全局配置。Worker 不是权限沙箱，必须有签名、权限声明、能力 allowlist、版本兼容、故障隔离和卸载/恢复合同。

不向公共生态公开任意第三方 `in_process` Python host，不执行任意 `entrypoint`，不承诺 Python host 无重启热卸载；Phase5A 的本地包只允许固定 `host/factory.py:create_host` 合同，并明确告知用户其代码会执行。对外 SDK 至少等两个真实 Worker 和一个外部资源包样例经过本地事务、Windows 和证据门后再评估。

## 7. 资源接口与 Worker 预览前置（2026-10-02）

资源接口正式开放依赖 4B-1.5 资源硬门、4B-2 租约和 4B-3 本地事务；在此之前可维护内部样例和验证工具，但不承诺公开兼容。受控官方 Worker 包和外部 Worker 开发者预览还必须等待至少一个真实可拔除官方功能样板，以及签名、能力 allowlist、数据隔离、故障恢复和 Windows 文件占用证据。

继续禁止任意第三方 `in_process` Python host、任意 `entrypoint` 和 Python host 即时热卸载。资源包的内容目录、配置、缓存和密钥作用域与功能包分开，Worker 进程隔离也不自动等于权限沙箱。

### 完成后的实际使用效果

作者现在可以先阅读路线、制作内部资源样例和运行本地验证，但不能把当前代码或 manifest 直接当作稳定公开 SDK；真正开放会在资源硬门和官方可拔除样板之后发生。
