# 用你的三视图做自己的键鼠跟随桌宠（素材生成 + 提示词包）

- 日期：2026-09-15
- 适用：模式「键鼠跟随」（复用 BongoCat 运行时）——素材契约见
  `docs/KEY-MOUSE-MODE-ASSETS-2026-09-13.md`，架构见 `docs/KEY-MOUSE-MODE-2026-09-13.md`
- 工具：`scripts/prepare_bongo_own_character.py`（准备工作区 + 预览图）、
  `scripts/restyle_bongo_key_overlays.py`（整套按键覆盖图换风格）、
  `scripts/verify_bongo_assets.py`（校验）

## 0. 先看清你能做到哪一层（决定要花多少时间）

| 路线 | 你能换掉什么 | 需要什么 | 时间 | 形状是否变 |
| --- | --- | --- | --- | --- |
| **A 贴图重绘**（推荐） | 角色的画风、配色、花纹、表情细节 | 三视图 + 原贴图 + GPT | 30–90 分钟 | 轮廓仍是原版猫的部件形状 |
| **B 覆盖图 / 背景 / 封面** | 按键高亮的样式、窗口背景、偏好页封面 | GPT | 10–30 分钟 | 与角色无关 |
| **C 完整自制模型** | 真正的形状与动作（想要"另一只生物"） | 三视图 + 拆件图 + **Live2D Cubism Editor 手工绑定** | 数天 | 完全自定 |

A + B 可以叠加：先用 A 把猫换成你的角色，再用 B 统一按键高亮风格。
**C 无法跳过 Cubism Editor**——GPT 只能出静态拆件图，绑定/导 `moc3` 必须人工。

## 1. 准备工作区（别在运行时目录里原地改）

运行时目录会在升级/重建副本时被覆盖，所以先把素材复制成一份工作区：

```powershell
# 1) 准备：复制出一套可编辑素材 + 生成"结构参考"预览图
python scripts\prepare_bongo_own_character.py `
  --model-dir "$env:APPDATA\dsh-pet-standalone\bongocat\runtime\assets\models\standard" `
  --out D:\dsh-pet-mycat --name mycat

# 2) 看一眼清单：哪些是"结构必须逐像素保留"的贴图、哪些可自由替换
#    （脚本已经打印；预览图在 D:\dsh-pet-mycat\preview\）
```

你会得到：

```text
D:\dsh-pet-mycat\
  mycat\                      ← 你的工作区（改这里的文件）
    cat.model3.json           ← 不要改名/不要改引用
    demomodel.moc3            ← 绑定才动
    demomodel.1024\
      texture_00.png          ← 模型贴图（1024×512，结构必须保留）
      texture_01.png
      texture_02.png
    resources\
      background.png          ← 窗口背景（可自由替换）
      cover.png               ← 偏好页封面（可自由替换）
      left-keys\*.png         ← 按键覆盖图（可自由替换）
      right-keys\*.png
  preview\                    ← 棋盘底预览图（贴给 GPT 当"结构参考"）
```

**贴给 GPT 的图**：`preview\...` 里的棋盘底预览（比透明原图更容易让它理解"哪里不能动"），
外加你的三视图。

## 2. 路线 A：把猫换成你的角色（贴图重绘）

### 2.1 提示词 A1 —— 贴图结构保真重绘（主提示词）

> 用法：新开一个会话，**同时上传两张图**，按下面顺序说明，然后粘贴提示词。
> 图 1 = 你的角色三视图（风格参考）；图 2 = `preview\demomodel.1024__texture_00.png.png`（结构参考）。

```text
我要做一张 Live2D 贴图的"结构保真重绘"，请严格按下面的规则执行。

【我给的两张图分别是什么】
- 图 1：我的原创角色三视图（正面/侧面/背面）。它是【风格与设定唯一参考】：
  造型语言、配色、花纹、眼睛画法、线条粗细都以它为准。
- 图 2：一张 1024×512 的 Live2D 贴图（棋盘格背景是透明区示意）。
  它是【几何结构唯一参考】：所有部件的位置、朝向、大小、比例、留白、透明区域
  必须与它逐像素一致，不许移动、旋转、缩放、增删任何部件。

【任务】
把图 2 里的每个部件（头、耳、眼、前肢/爪、身体、尾巴、装饰等）按图 1 的角色
设定重新上色与重绘线条，但保持图 2 的部件布局与透明区域完全不变。

【硬性要求】
1. 输出画布尺寸必须与图 2 完全一致（1024×512），不得裁切、不得放大单侧；
2. 每个部件的形状轮廓、位置、朝向、占比、相互间距不变；
3. 透明区域仍为透明（不要用白色/棋盘格/渐变色填充背景）；
4. 只使用图 1 里的配色，允许为阴影/高光加入同色系深浅变化；
5. 线条风格统一：干净描边（约 5–6 像素视觉宽度），扁平化上色 + 一点高光；
6. 不要新增部件（不要加文字、logo、道具、背景、水印、签名、边框）。

【不要做的事】
- 不要"重新构图"、不要"优化构图"、不要镜像、不要居中重排；
- 不要把部件合并或拆分；
- 不要改变透明区域的覆盖范围（哪怕 1 像素的边缘扩张也可能造成穿帮）。

输出：一张 1024×512 的 PNG。
```

### 2.2 提示词 A2 —— 第二、第三张贴图（保持一致）

同一会话里接着做 `texture_01.png`、`texture_02.png`：先上传对应的预览图，然后：

```text
现在用完全相同的规则处理我新上传的这张贴图（同样 1024×512、同样结构保真）。
额外要求：配色、线条粗细、阴影方向必须与上一条消息里你生成的贴图完全一致
（同一个角色、同一套光照），只换部件内容，不要换风格。
```

> 一致性技巧：尽量同一个会话连做三张；如果风格漂移，把上一张成品也一起上传，
> 让它"对照上一张的调色板"。

### 2.3 尺寸不对怎么办（重要）

有些图像工具只会给"同比例"输出（例如 1536×768）。Live2D 的 UV 是**归一化**的，
所以**等比缩放整张图**是安全的：把 GPT 的输出按比例缩放回 1024×512（不要裁切、
不要改宽高比），结构就不会错位。缩放完再跑校验：

```powershell
python scripts\verify_bongo_assets.py --dir D:\dsh-pet-mycat\mycat
```

### 2.4 透明底怎么拿到

如果 GPT 只能给不透明背景：让它用**纯品红 #FF00FF** 当背景，然后用这段脚本抠成透明：

```python
# 存为 to_alpha.py，然后 python to_alpha.py 输入.png 输出.png
import sys
from PIL import Image
src, dst = sys.argv[1], sys.argv[2]
im = Image.open(src).convert("RGBA")
px = im.load()
for y in range(im.height):
    for x in range(im.width):
        r, g, b, a = px[x, y]
        if r > 200 and g < 60 and b > 200:      # 品红 → 透明
            px[x, y] = (0, 0, 0, 0)
im.save(dst)
```

## 3. 路线 B：按键覆盖图 / 背景 / 封面

### 3.1 提示词 B1 —— 一张"按键高亮"样式图（配脚本批量铺满整套键）

按键覆盖图是**整窗大小的透明 PNG**，每个键一张（50 多张）。你自己一张张画不现实，
所以正确做法是：只让 GPT 生成**一张**高亮样式图，然后用脚本按原图的透明区域
批量套用——位置天然正确。

```text
请生成一张用于桌面宠物"按键高亮"的透明背景 PNG 插画，正方形 1024×1024。

内容：一枚按下去的键帽 + 从键帽边缘溢出的柔和高光，造型与配色跟随我上传的角色
三视图（如果你能看到附件）：
- 键帽本体：浅色磨砂质感，圆角，顶部有一点点下凹的阴影；
- 高光：从键帽四周向外扩散的柔和光晕，颜色取角色主色的亮调；
- 可以带一个角色的小爪印或小符号作为键帽上的装饰。

硬性要求：
- 纯透明背景（不要棋盘格、不要地面、不要投影到画布边缘）；
- 主体居中，四周至少留 10% 透明边距；
- 不要出现任何文字、字母、数字、logo、水印或签名；
- 光晕不要过曝，边缘要柔和过渡（不要硬边方形色块）；
- 输出正方形 PNG。

负面提示：文字、键盘阵列、多个键帽、写实照片、噪点、渐变网格、深色背景。
```

拿到这张图后，一条命令把整套按键覆盖图换成你的风格：

```powershell
python scripts\restyle_bongo_key_overlays.py `
  --overlay-dir D:\dsh-pet-mycat\mycat\resources\left-keys `
  --style D:\dsh-pet-mycat\style-keycap.png `
  --out D:\dsh-pet-mycat\mycat\resources\left-keys --backup

# right-keys 同理（方向键只有 4 张）
```

参数说明：`--keys Space,Return,KeyA` 只处理指定键；`--fit stretch` 让样式图拉伸铺满
（默认 `contain` 保持比例、不会变形）；`--backup` 把原图备份到同目录的 `_orig\` 子目录
（不要在原目录留 `*.png.orig` 之类的文件——素材校验器只允许按键目录里出现 PNG）。

> 只想先看效果？先处理 4 个键：`--keys Space,Return,KeyA,KeyS`。

### 3.2 提示词 B2 —— 窗口背景 `resources/background.png`

```text
请生成一张桌面宠物窗口背景图，透明背景 PNG，尺寸 1024×512（宽×高）。

主题：与上传的角色三视图同色系的极简氛围背景——画面正中留空（角色会叠在上面），
四周可以有淡淡的光斑、星点、飘带或几何色块；整体低对比、低饱和，颜色偏角色主色。

硬性要求：
- 中央 60% 区域保持完全透明，避免干扰角色；
- 不要出现文字、人物、动物、logo、水印、签名；
- 不要强烈渐变或高对比色块压在角色区域；
- 输出 PNG，不要白色或棋盘格背景。
```

### 3.3 提示词 B3 —— 偏好窗口封面 `resources/cover.png`

```text
请生成一张桌面宠物模型的封面缩略图，PNG，1024×512（宽×高，横向）。

内容：以我上传的三视图角色为主角，正面半身或坐姿，居中偏左，右侧留白；
背景是同色系的浅色圆形色块渐变（不透明），角色描边干净、配色与三视图一致。

风格：扁平化卡通、粗描边、柔和阴影、明亮通透。
硬性要求：不要文字、logo、水印、签名；不要裁切主体；不要写实照片质感。
```

## 4. 路线 C：完整自制模型（要换形状时才走）

### 4.1 提示词 C1 —— 把三视图变成"拆件图"

GPT 只能给你静态素材，接下来必须在 Live2D Cubism Editor 里手动绑定。
为了让绑定省事，拆件图要满足"部件互不重叠、留边、同一张画布"。

```text
我要做一套 Live2D 用的"拆件图"（把角色拆成可独立变形的部件），
请基于我上传的三视图，输出一张 2048×2048 的透明背景 PNG。

必须包含的部件（每个部件各自独立、互不重叠、不接触）：
- 头部：后脑/主头形、左右耳（分开）、耳朵内侧（分开）
- 面部：左眼（上眼睑+瞳孔合一）、右眼（同）、眉/眼影（可选）、嘴、脸颊腮红
- 身体：躯干、腹部/肚皮（分开）、尾巴（分 2–3 段，便于摆动）
- 四肢：左前肢（上臂+手爪，分开）、右前肢（同）、左后腿、右后腿
- 装饰：项圈/围巾/挂饰（若有）

排版要求：
- 所有部件平铺在同一张 2048×2048 透明画布上，相互间距 ≥ 24 像素，彼此不重叠；
- 部件按"头在上、身体居中、四肢在下、装饰靠边"的常规区域摆放；
- 每个部件保持它在角色上的朝向（不要为了排整齐而旋转部件）；
- 输出纯透明背景；不要合并部件；不要加描边特效、阴影投射、背景色；
- 不要文字、标注、箭头、水印、签名。

风格：与三视图完全一致（配色/线条/阴影方向统一）。
```

### 4.2 绑定要点（Cubism Editor）

1. 把拆件图按部件切分图层，建网格、设变形器（头、眼、口、双臂、尾等）。
2. 参数名必须与运行时对齐（否则键鼠跟随不生效）：

| 参数 | 用途 |
| --- | --- |
| `CatParamLeftHandDown` / `CatParamRightHandDown` | 左手/右手按下（键盘输入触发） |
| `ParamMouseLeftDown` / `ParamMouseRightDown` | 鼠标左/右键按下 |
| `ParamMouseX` `ParamMouseY` `ParamAngleX` `ParamAngleY` `ParamAngleZ` `ParamEyeBallX` `ParamEyeBallY` | 鼠标位置跟随（头/眼/身体朝向） |
| 组 `EyeBlink`（`ParamEyeLOpen`、`ParamEyeROpen`） | 自动眨眼 |

3. 导出 `moc3` + 贴图 + 表情 + 动作，替换掉工作区里同名文件，`cat.model3.json`
   的文件引用结构不要改；贴图目录名里的数字是**宽度**约定（如 `demomodel.1024` = 宽 1024）。
4. 跑校验 + 实机验证（见第 5 节）。

### 4.3 提示词 C2 —— 动作/表情参考帧（可选）

`.motion3.json` / `.exp3.json` 的关键帧必须在 Cubism Editor 里做。想要新动作时，
让 GPT 出参考帧，你照着摆姿势：

```text
基于我上传的三视图，生成同一角色的三张姿势参考图（每张单独输出、透明背景、同一机位与比例）：
1) 起势：双爪抬到胸前，身体略前倾；
2) 中段：左爪向下压（像敲键盘），右爪悬停；
3) 收势：双爪落回身侧，身体回正。
每张都保持相同画布尺寸与角色大小，不要加背景、文字、道具。
```

## 6. 常见翻车点与对策

| 现象 | 原因 | 对策 |
| --- | --- | --- |
| 模型出现"错位/撕裂/部件跑到别处" | GPT 重新排版了贴图位置，或输出尺寸比例被改 | 只接受"结构逐像素一致"的结果；用等比重缩放回 1024×512；跑校验脚本看尺寸 |
| 角色边缘出现白边/品红边 | 背景没有被正确抠掉 | 用 `#FF00FF` 纯色背景 + 第 2.4 节脚本，或让 GPT 直接输出透明底 |
| 按键高亮位置对不上 | 直接让 GPT 重绘了整张覆盖图并"优化构图" | 用 `restyle_bongo_key_overlays.py`：位置永远取自原图 alpha |
| 三张贴图风格不一致 | 分散在不同会话里生成 | 同一会话连做三张，或把上一张成品一起上传做对照 |
| 键盘模式（keyboard 模型）没有颜色变化 | 只替换了 standard 模型 | 想换键盘模型就同样替换 `models\keyboard\` |
| 运行后还是旧素材 | 没有退出重进模式，或放错数据目录 | 退出并重进模式；确认目录是 `<数据目录>\bongocat\models\<模型名>\` |
| 校验报 `texture-size-mismatch` | 贴图宽度与目录名约定不符 | 目录名 `.1024` 表示宽 1024；把贴图等比缩放到宽 1024 |

## 7. 提示词通用技巧（贴给 GPT 时的 5 条）

1. **先说清"哪张图管什么"**：三视图 = 风格唯一参考；原贴图/预览图 = 结构唯一参考。
   不写清楚，模型默认会按自己的审美重排构图。
2. **用"必须/不得"这种硬约束**写要求，并显式列出负面清单（加文字、加背景、重排、镜像）。
3. **一次只改一样**：先改画风，再单独换高亮/背景，出问题一眼能定位。
4. **要求它"不要优化构图"**——这是贴图类任务最常见的翻车原因。
5. **产出立刻跑校验脚本**，别等装进包里才发现尺寸/缺件问题。
