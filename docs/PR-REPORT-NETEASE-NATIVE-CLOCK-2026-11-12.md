## 一、核心特性

网易云的 SMTC 会话可报告曲名与播放状态，但本机不提供有效进度；原歌词时钟只能估算，无法判断同曲重播。本次保留现有 SMTC 选曲和过滤，只在其选中 `cloudmusic.exe` 且缺少位置时，补充只读原生时间轴。

当前支持经实测的 Windows x64 网易云 **3.1.42.205594**，`cloudmusic.dll` SHA256 为 `557d7706dedc8556a8bd279d4dfe2bc05b80ad729a8749caccd9e29916935493`。其他构建仍走原有估算和手动对齐，不宣称覆盖全部 3.x。曲目身份、播放状态不匹配时不合并；不修改播放器、不安装插件、不注入 DLL。

用户可见变化：从中途开始、快进/回拖和单曲重播可跟随真实位置；暂停时拖动会更新冻结位置；原生读源消失后重新开放「歌词对齐」，读源恢复后自动接管。

## 三、实现要点

- 从 `OrpheusBrowserHost` 主窗口识别同会话播放器，包含隐藏窗口；多个播放器或任一归属查询失败均拒绝合并，renderer 进程不算独立播放器。
- 使用 `PROCESS_QUERY_INFORMATION | PROCESS_VM_READ`（`0x410`）；核对可执行文件、同目录 DLL、精确文件摘要、映像大小和已加载指令。仅在连接时解析模块与 DLL，热态复用句柄和声明类型。
- 位置和播放对象地址通过唯一特征及相对位移解析；对象字段仍受具体构建白名单约束。读取曲目标识前后校验一致性，拒绝 NaN、越界值及非播放/暂停状态。
- 只读取 `playingList`、`fmPlay`，按采样 ID 找歌曲并核对标题、歌手和可用专辑；不读取账号数据库。元数据只缓存当前 ID，文件半写入可重试。
- 实机发现切换时状态会暂为 `4`，循环末尾可能略超过时长；这些快照不作为真值，也不触发 5 秒硬失败退避，下一拍即可恢复。未知构建、拒绝访问等连接失败才关闭句柄并退避。
- 新对象归现有歌词采样线程所有，`finally` 关闭句柄；Qt 通信沿用既有 queued signal，不新增线程或 QObject。SMTC 自身阻塞问题仍由安装版既有进程隔离补丁负责，此源码改动不冒称线程本身能隔离 WinRT 持 GIL。

GitHub 调研采用 [AF-Media-Bar 的 NetEase 实现](https://github.com/Fervent-Tempo/AF-Media-Bar/blob/main/src/AFMediaBar/Classes/Services/Media/Sources/NetEase/NetEase.cs) 所记录的指令与对象布局方向，独立实现 Python 读取与融合，并保留 MIT 声明。没有移植 netease-watcher 的 hook，也没有安装 BetterNCM/InfLink。

## 四、性能分析

环境：Windows 11，Python 3.11.15，源测试 PySide6 6.12.0；冻结探针使用已安装 EXE 的 Python 3.11 与原 `_internal`。所有实机样本来自真实播放器，采样进程与播放器在交互用户会话。

复现命令：

```text
python scripts/bench_netease_position.py --samples 40 --interval .1 --smtc --output native.json
native-clock-probe.exe --samples 60 --interval .1 --smtc --output frozen-native-live.json
```

| 测量 | 样本 | 首次连接 | 原生读取均值 | 完整热态补充均值 / 最大值 | Qt 最大心跳间隔 |
|---|---:|---:|---:|---:|---:|
| 首轮正常播放 | 40 | 87.53 ms | 0.111 ms | 未测 | 18.54 ms |
| 暂停 | 20 | 110.13 ms | 0.122 ms | 2.520 / 6.363 ms（19 次） | 21.28 ms |
| 最小化播放 | 40 | 115.60 ms | 0.220 ms | 2.023 / 5.203 ms（39 次） | 41.11 ms |
| 冻结候选播放 | 60 | 131.37 ms | 见原始 JSON | 2.850 / 6.873 ms（59 次） | 24.80 ms |
| 并发测试期间的换曲后读取 | 10 | 106.53 ms | 0.122 ms | 9.449 / 20.833 ms（9 次） | 33.73 ms |

完整补充路径包含主窗口归属检查、原生读取和曲目匹配，不包含此前已完成的 SMTC 查询；不得把约 0.1 ms 的原生读取称为完整查询耗时。首次连接包含 DLL 校验，完整补充首查可能复用已预热 DLL 缓存，二者不能直接横比。

前三轮完整补充热态均值约 2–3 ms/次；并发测试期间另一轮为 9.45 ms，未隔离系统负载，不将前者当作固定上限。沿用原采样频率；原先没有此原生补充路径，不声称 SMTC 查询本身加速。新增 Win32 枚举/只读内存调用；连接时读取 DLL，换曲/元数据未命中时读取两个本地元数据文件，无新增网络请求、线程或进程。

40 次最小化采样中，连接后到采样结束句柄均为 233，私有内存均为 21,467,136 字节；工作集增加 32,768 字节。SMTC 导入会另有一次性资源增长，不能混算成原生句柄泄漏。50 秒重播探针含保存 250 次观测的列表，连接后私有内存增加 65,536 字节，关闭 reader 后句柄减少 1。短样本不代表长期无增长，Qt 心跳也不等同于桌宠呈现帧率。

## 七、已知限制与后续

仅在已验证 DLL 的原生客户端提供补充；网易云更新后可能回到手动校准，需要重新核验构建和动态行为后扩展白名单。客户端未提供可匹配元数据、本地歌曲未列入两种元数据源、多个播放器实例或 SMTC 没选中网易云时不补充。

原采样仍受 SMTC 查询耗时影响，拖动/循环不会保证毫秒级显示响应；原生值之间沿用现有歌词插值。状态切换瞬间可能继续估算至下一次有效读数，未伪造重播信号。

候选 EXE 是本机增量维护产物，不是完整官方发布构建。源码、冻结执行、安装部署和桌宠可见验收是四项独立结论。
