依赖约束

engine/ 不导入 Qt动画、几何、物理、行为都在这里，可以在无窗口环境下测试。
contracts/ 只用标准库端口用 Protocol 声明；实现放在 UI、平台或领域模块。
pet.* 只允许两个适配层petcore/media/ 与 petcore/content/legacy.py 可以导入旧包。
网络库集中在三个包urllib、socket、requests 等只允许出现在 net/、api/、account/。
ui/ 单向依赖依赖 engine/contracts/media/content/mods/platform；core 不反向依赖具体业务扩展。
密钥只进系统钥匙串config.json 与 api.json 不写 API Key；第三方偏好落 config.extra。

约束由 tests/test_petcore_architecture.py 检查。

启动路径

正常启动与 --check 走同一条内容加载链路；--check 不创建窗口，不写配置。

1
解析参数petcore/cli.py

--root 指定数据根，--portable 与 --instance 切换数据根，--allow-feature-mods 打开功能扩展总开关，mods 子命令走命令行分支。

2
加载配置Config.load(data_root)

读取 config.json、各 slot 的 config-pet-N.json、mods-state.json；--check 使用 persist=False，不落盘，也不创建迁移备份。

3
单实例锁QLockFile

同一数据根只允许一个进程；--instance NAME 使用独立数据根与独立锁，可以并行启动多份。

4
创建 CoreHostpetcore/ui/app.py:406

组装进程级服务：QtScheduler、音频路由、记忆、Webhook、API 规格与钥匙串、账户与余额、语音与 ASR、DSH 客户端、社区、聊天控制器、快速对话、截图问答、菜单模型、免打扰、WorkerHost、市场任务。

5
加载内容与扩展CoreHost.load_content · mods/loader.py

只读加载 assets/characters，然后扫描 mod 目录；content 包进入角色列表，feature 包通过 manifest 与授信检查后由 FeatureManager 装配。

6
创建宠物窗口PetManager · PetWindow

动画目录、播放器、行为决策、ClipLibrary（frameseq → webm → gif 回退）；恢复位置、屏幕、缩放；首帧渲染后显示。多宠时 slot 1..98 各自有配置文件。

7
注入端口并启动 runtimepetcore/ui/ports.py:981

HostPorts 声明 27 个字段，这里注入 22 个；7 个 Core 内置 feature 无条件加载，用户 feature 通过 runtime.start() 启动，菜单贡献合并进「扩展」子菜单。

8
托盘、菜单与监听器TrayIcon · MenuModel · SessionWatcher

托盘菜单独立于右键菜单；屏幕变化、锁屏/睡眠、全屏检测、灵动岛采样按需启停。

9
进入事件循环QApplication.exec()

之后所有 GUI 操作都在主线程；扩展的跨线程回调经 QtScheduler 排队。

--check 与 --check --strict --check 输出角色、每段动画实际采用的后端、mod 列表与诊断、配置快照；只读，不写文件。 构建门使用 --check --strict 并检查 check.json。
04

扩展机制

feature 包提供代码与 UI 贡献；content 包提供角色与素材。加载步骤固定，单步失败只产生诊断，不阻断 core 启动。

feature 功能包

  • 包含 mod.json、entrypoint 和 Python 代码。
  • 可提供菜单、设置页、对话窗页与命令。
  • 安装到 <data_root>/mods/<id>，或由安装器投放到 {app}/mods/<id> 并带 .trusted。
  • 受 allow_feature_mods 总开关与授信检查约束。

content 内容包

  • 角色与素材包，id 形如 character.<名字>。
  • 禁止携带可执行文件；manifest 校验会拒绝。
  • 由 content/collect.py 收集为 CharacterSpec。
  • 与 feature 包共用扫描、版本与路径校验。

feature 加载顺序

1. 扫描数据目录 mods → 安装目录 mods → 仓库 mods → 额外目录；同 id 后者覆盖
→
2. 校验mod.json schema、id、version、api_version、路径逃逸、content 包可执行文件检查
→
3. 授信feature 必须在用户 mods 内，且 allow_feature_mods 开启或安装目录带 .trusted
→
4. 导入入口entrypoint 必须是包内相对路径；host/__init__.py 按包加载，支持相对 import
5. create_host收到 FeatureContext：owner、core_version、api_version、ports、host、log
→
6. FeatureDefinitioncontributions、runtime_factory、settings_factory、view_factories
→
7. runtime.start()订阅、定时器、加载数据；命令表 runtime.commands 在这里暴露
→
8. 贡献落地菜单项、设置页、对话窗页进入 core 的 UI 槽位

贡献类型

petcore/contracts/contributions.py 现有 11 个 kind。运行期有消费点的是 3 个；角色内容走 content 收集器，不走 contribution。

kind用途运行期消费点状态
menu右键菜单项FeatureManager.menu_contributions() → MenuModel生效
settings_page设置页FeatureManager.settings_pages() → ExtensionsPage生效
chat_view对话窗里的一页FeatureManager.chat_views() + view_factories生效
command、hotkey、card、install_hook、phrases、sound、theme、seasonal清单允许的声明当前没有消费方；命令表使用 runtime.commands无消费点

端口

HostPorts 声明 27 个字段，build_ports() 注入 22 个。未注入的 5 个在运行期为 None。

已注入的 22 个

  • 呈现与交互：presentation、pets、interaction、quiet、reminders、audio
  • 数据与配置：storage、credentials、resources、config
  • 通信与模型：http、api、chat、quick_chat
  • 屏幕与系统：screen、screen_ask、system
  • 运行时：scheduler、worker、speech、memory、webhook

未注入的 5 个

  • commands：命令表使用 runtime.commands。
  • menu：菜单使用 contribution 注册。
  • windows：没有窗口端口；扩展自建窗口。
  • input：拖文件使用 interaction.on_drop。
  • capabilities：能力只做声明，没有运行期检查。

线程规则

  1. Qt 控件、窗口、气泡、菜单、托盘只在 GUI 线程操作。
  2. scheduler.call_later 是唯一允许从任意线程调用的端口；回调在 GUI 线程执行。
  3. http.request、http.get_json、speech.synthesize 会阻塞；调用方自己开线程，结果经 scheduler 回 GUI。
  4. stop() 里取消定时器、订阅和监听器；Runtime.close() 不由 core 调用。
  5. 迟到的结果用代次号、取消事件或 guard 丢弃，避免写入下一轮状态。
05

运行时与数据

core 提供窗口、端口、配置与数据目录；具体业务能力由内置 feature 或示例 mod 提供。

动画与行为

  • GraphCatalog 读取动画目录；AnimationPlayer 推进帧；BehaviorDirector 选择待机、转向、动作、移动。
  • ClipLibrary 按 frameseq → webm → gif 的顺序选择后端。
  • engine/ 计算位移、夹取、碰撞与几何；media/ 负责解码。

多宠与碰撞

  • PetManager 管理所有 slot；主宠使用 config.json，子宠使用 config-pet-N.json。
  • 碰撞按 tick 计算；碰撞几何在 engine/collision.py，窗口位置由 PetWindow 应用。
  • 跨屏与位置恢复由 platform/screens 与配置中的屏幕名、比例决定。

设置与菜单

  • 设置页在 ui/settings/；扩展设置页聚合到「扩展管理」。
  • 菜单项与设置落点的对应关系由 ui/settings/coverage.py 与测试约束。
  • 菜单布局、热键、自启、多宠 profile 都由 core 管理。

聊天、语音、截图、灵动岛

  • 对话窗、快速对话、截图动作条、灵动岛窗口在 core。
  • AI 对话、OCR、音乐识别、天气等业务能力由 petcore/builtin 或 examples/petcore-mods 提供。
  • 网络访问统一经 net/；API 规格与钥匙串在 api/ 与 account/。

构建与验证

两条运行时有独立的入口和打包配置；架构约束、设置覆盖与文档同步都由测试检查。

常用命令

python -m pytest -q
ruff check .
python -m petcore --check --strict --out dist/check.json
python -m petcore --root ""

--check 只读；--strict 用于构建门。

  • PyInstaller onedir；入口为 packaging/petcore_entry.py 或 packaging/pet_entry.py。
  • 安装包使用 Inno Setup：packaging/petcore.iss、packaging/dsh-pet.iss。
  • 安装器投放的官方 feature 包带 .trusted，用户导入的包不带。

边界与常见误判

这些行为由当前实现决定；改扩展或排查问题时先核对。

边界实际行为
同进程扩展与 core 共用 Python 解释器；扩展的死循环会阻塞桌宠 tick，原生崩溃会终止整个应用。没有沙箱。
capabilitiesmanifest 中的声明，用于展示与安装提示；运行期没有权限检查。
execution: "worker"manifest 允许该值，当前加载器不加载；ui/app.py:750 记录 worker feature is not supported yet。
窗口没有窗口端口。扩展需要在菜单命令里自建 QDialog 或 QWidget，并自己管理显示、置顶、关闭与定时器。
重新加载stop_owner() 撤销订阅，runtime.stop() 清理，清掉包目录下的 sys.modules 后重新导入；没有模块级热卸载。
可选端口5 个端口恒为 None；调用前先判空，缺失在精简包或非 Windows 环境中属于正常状态。
配置文件pet/ 与 petcore/ 使用不同的文件名；迁移或排障时先确认运行时。
不要用 capabilities 代替安装审查 能力声明只描述扩展打算使用什么。真正决定扩展能否运行的是安装位置、.trusted 标记与 allow_feature_mods 开关。
