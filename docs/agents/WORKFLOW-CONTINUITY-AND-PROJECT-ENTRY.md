# 施工记录、交接与项目入口规范

> 本文是当前项目的协作规则，不是某一次施工的历史报告。它把计划、实施记录、跨对话交接和开发者入口串成一条可追溯路径。

## 1. 固定的计划与汇报结构

正式计划和汇报正文保持严肃工程顺序：

1. 当前事实与目标；
2. 范围、非目标和边界；
3. 方案、接口、行为变化和风险；
4. 实施顺序、依赖、停止条件和回滚；
5. 已执行命令、环境和实际结果；
6. 修改文件和证据；
7. 未完成、待确认和下一步；
8. 最后追加“完成后的实际使用效果与限制”。

“最后的实际使用效果”必须说清用户能看到什么、原有操作是否变化、是否能关闭/卸载、Core 与 Worker 如何连接、哪些只是后续目标，不能把内部拆分数量宣传成可拔除交付。

汇报必须分开写：计划、已实现、自动化通过、Windows/其他实机通过、用户确认、已提交、已推送。历史结果注明对应版本或日期；未手测不等于故障，自动化通过不等于用户验收。

## 2. 每个持续任务的记录集合

每个正式且可能跨对话继续的任务保留以下记录：

| 记录 | 位置 | 作用 |
|---|---|---|
| 设计与验收详情 | `docs/` 对应阶段 | 目标、接口、方案、验收矩阵、风险和回滚 |
| `PLAN.md` | `.scratch/<任务名>/` | 稳定编号的任务、依赖、完成证据 |
| `WORKLOG.md` | `.scratch/<任务名>/` | 施工步骤、动作、状态、证据和准确停点 |
| `HANDOFF.md` | `.scratch/<任务名>/` | 暂停或交接时可以立即执行的下一步 |
| `STATUS.md` | `.scratch/<任务名>/` | 当前状态、验收门、提交/推送状态 |
| `SUMMARY.md` | `.scratch/<任务名>/` | 交给新对话的精简最终有效事实 |

用户要求的“四份基础记录”仍然保留；`WORKLOG.md` 和 `SUMMARY.md` 是为施工过程和跨对话续接新增的两份，不替代设计、计划、交接和状态。

### `WORKLOG.md` 最小格式

每个步骤至少记录：步骤编号、目标、涉及文件、执行动作、状态（未开始/进行中/已完成/阻塞/待验证）、证据、未解决问题、准确停点、下一步。

只写对后续工作有用的过程证据。不要写完整失败堆栈、已排除的重复尝试、构建缓存、原始日志、密钥或无关讨论。

### `SUMMARY.md` 最小内容

至少包含：

- 任务目标；
- 项目、分支和工作树状态；
- 已完成事项；
- 已修改/新增文件；
- 关键架构和路线决策；
- 尚未完成事项；
- 当前阻塞与风险；
- 用户已经确认的计划；
- 用户偏好的回答方式；
- 必须保护的文件和边界；
- 新对话优先阅读的文件；
- 下一步准确动作；
- 当前提交、推送和验证状态；
- 面向用户的实际效果与限制。

总结只保留最终有效事实，不把失败调试过程当作项目知识库。

## 3. Git、推送和子智能体边界

- 默认不开子智能体；只有用户在当前任务中明确要求时才使用。
- 用户明确要求或阶段需要回滚点时，可以创建本地提交作为备份。提交前使用显式文件列表，检查暂存范围、敏感文件和保护文件。
- 本地提交不等于远程发布。`git push` 需要当前任务的明确授权；授权不会自动延续到下一次任务。
- 不使用 `git add -A`、`git add .`、`reset --hard`、强推或覆盖用户已有改动。
- 施工记录中的“已提交”“已推送”必须分开填写；没有实际远程核验，不得写已推送。

## 4. 新对话的阅读入口

新对话默认按以下顺序读取：

1. [`docs/PROJECT-ENTRY.md`](../PROJECT-ENTRY.md)；
2. 当前任务 `.scratch/<任务名>/STATUS.md`；
3. `PLAN.md`；
4. `HANDOFF.md`；
5. `SUMMARY.md`；
6. 阶段设计与验收详情；
7. `docs/INDEX.md` 中被任务引用的专项文档。

`docs/PROJECT-ENTRY.md` 是渐进式披露入口；`docs/INDEX.md` 仍是仓库文档的权威索引。入口文档只提供导航和当前状态，不复制所有设计细节，避免长期漂移。

## 5. 历史记录纪律

- 已关闭且不再作为当前入口的历史任务不批量补写 WORKLOG/SUMMARY。
- 历史报告保留原结论，不把后续测试倒写进去；新事实写在当前阶段报告、状态记录或新总结中。
- 旧构建产物和旧测试结果只能作为历史证据，必须注明版本/日期，不能冒充本轮结果。

## 6. 完成后的实际使用效果

这套规范不会改变桌宠界面。它会让新对话可以从 `docs/PROJECT-ENTRY.md` 开始，读取当前任务的状态、计划、停点和总结，直接继续工作；开发者也能清楚区分“Worker 已独立运行”“功能已可停用”“功能包已物理卸载”这三种不同完成度。文档施工有本地可回滚记录，但不会在未授权时自动推送远程。
