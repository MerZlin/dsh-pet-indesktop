# 使用 MOD 管理中心

[返回教程入口](README.md) · [角色制作](CHARACTER-PACKS.md)

## 安装和立即启用
1. 打开设置 → 扩展管理，选择「导入 ZIP」或「导入目录」。选完整包，目录根必须有 `manifest.json`，不要选择仓库根或单独的 videos。
2. 导入成功后列表出现一行；新包是**未启用**。不需要 owner、ID、用途授权或技术预检。
3. 点「启用」。功能入口与设置贡献即时刷新，不必关闭设置；点行内「设置」定位该扩展。扩展自身设置仍需点「保存此扩展设置」。
4. 角色的「启用」只是加入可选角色；点「使用」才给当前设置对应的桌宠实例换装。多开实例不会跟着换。

顶部搜索按名称、说明和 ID 查找；「全部 / 角色资源 / 功能扩展」只筛选本地已存在的包。历史版本不重复占行。没有说明的旧包显示「作者未提供说明」。内置或手动放置的角色注明来源，不能在此删除源素材。

## 更新、停用与删除
- 「更新」选择该包新版 ZIP / 目录；不同 ID 会拒绝。更新保留原启停状态；同版本同内容提示已存在。同版本不同内容应让作者增加版本号后重打包。
- 已加载的 Python 代码不能假装热替换。看到「等待自然退出」时，先保存草稿并自然退出相关桌宠和设置，再打开；不要强杀或手动删除版本文件。
- 停用后旧菜单句柄不能继续执行；正在使用的角色先切回内置角色，媒体释放失败则保留包并给原因。
- 勾选多行出现「启用 / 停用 / 删除」。全选只选当前筛选结果；改搜索或筛选会清空选择。批量删除确认一次，结束汇总成功 / 待退出 / 未完成，逐行看原因。
- 「更多」提供完整说明、打开安装目录、删除安装副本和回滚上一版。说明是纯文本，不会执行 HTML。
- 删除只删除受管理安装版本；外部 ZIP、外部源目录、个人配置 / 聊天记录保留。内置资源和手动素材不提供管理器删除。

## 项目目录
```text
项目目录/
  dsh-pet-core-webm.exe
  portable.json
  data/
    config.json
    characters/<角色ID>/videos/                 # 手动素材
    content/characters/<角色ID>/versions/<版本>/ # 管理器安装角色
    plugins/<功能ID>/versions/<版本>/           # 管理器安装功能
    feature-data/<功能ID>/                      # 功能个人数据，删除 MOD 保留
```
不要手工修改安装版本、active.json 或功能账本。找原始 ZIP 应去自己下载/保存的位置，它不是 `data/plugins`。

## 常见问题
- 导入不识别：确认 ZIP 根/所选目录有完整 manifest；只有 videos 请走手动素材教程。
- 启用后没有设置：有些包不提供设置；先看对应行结果，失败不是启用成功。运行时异常需要作者修复。
- 弹出保存 / 放弃 / 取消：仅因为该扩展存在未保存编辑；其他页面的草稿不受本次操作覆盖。
- 更新等待退出：不是下载失败，是旧代码仍被使用。管理中心不强杀进程。
- **ZIP 导入的功能扩展用不了（已知未解决缺陷，2026-10-10）**：实机报告——通过 ZIP 导入 `examples/mods` 里的两个示例功能包（`hello-local`、`echo-worker`）时**操作未完成，报 `worker_probe_failed`**；同一份内容改用「导入目录」可以正常运行。**角色资源包（角色/动画）走 ZIP 导入正常。**本地非冻结环境无法复现该差异，因为探针沙箱只在冻结版里创建。排查结论与待补信息见[已知缺陷](README.md#四已知缺陷2026-10-10)。**规避办法：优先用「导入目录」导入。**

## 实际效果与限制
安装管理操作即时生效，扩展业务设置独立保存。Setup 全项目卸载仍按原来的个人数据选项执行，不等同于这里的单包删除。
