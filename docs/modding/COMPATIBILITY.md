# 兼容基线与后续拆包影响

[入口](README.md) · [API v1](API-V1.md) · [实施计划](MOD-CENTER-IMPLEMENTATION-PLAN-2026-10-10.md)

## 约定
1. `pet.mod_api.v1` 的公开定义、菜单、设置协议、自有配置 / 数据、按请求 API 和 Worker 接口形成版本基线。hello-local、echo-worker 与旧格式包被纳入回归。
2. 后续内部拆包由 Core 适配 v1，不在普通功能搬迁中要求作者改私有导入路径。
3. 如确需破坏性变化，新建 v2，提供 v1 适配与迁移说明，不直接删除 v1。增加可选字段使用默认值；旧 manifest 不因缺少 name / description 拒绝。
4. 包 manifest 写明适用 Core / API / 平台；不兼容应在导入时明确拒绝，不能勉强运行。
5. Python 私有模块、未公开窗口对象、其他 DLC 私有类以及系统 ABI 不享受上述保证。不要用“现在能 import”代替公开契约。

## 后续影响矩阵（本轮不实施拆分）
| 待拆能力 | Core 需要保留 / 适配 | 使用 v1 的 MOD 预期影响 | 仍需另行设计 |
|---|---|---|---|
| 音乐与歌词 | 通用挂载、启停、配置与菜单 | 自己的菜单 / 设置不改；不应导入 pet.music_* | 公共播放服务、曲目 / 歌词事件 |
| 语音 / TTS | API 配置解析、任务取消与生命周期 | 无私有依赖的 MOD 不需跟随文件搬迁 | 发音服务、音频设备与播放竞争策略 |
| Agent / 工具执行 | 配置隔离、执行状态和 Worker 契约 | 通用 Worker 和自有数据可保持 | 工具授权、跨 DLC 调用、会话所有权 |
| AI 继续解耦 | 主 API、贡献 / 窗口桥接适配 | 使用 API 端口的 MOD 不需复制 AI 私有代码 | 公共聊天服务（如需要） |
| 识屏继续解耦 | Worker 启动与取消、可信 runtime 根 | 通用 Echo 类型 MOD 不受截图实现位置影响 | 公共截图 / 视觉任务服务 |
| 角色与动画优化 | 内容 manifest、来源与当前实例语义 | 合规角色包保持相对路径和格式即可 | 新媒体格式应加能力声明或新版本 |

## 作者的稳定做法
- 从样例复制源码但更换唯一 ID、名称与版本；不复制 Core 私有模块树。
- 为自己的包保存最小回归：导入停用 → 启用 → 设置保存 → 执行 → 停用取消 → 更新 → 删除；保留源 ZIP。
- 请求前读最新 API，不缓存 Key，不依赖另一个 DLC 一定安装。
- host 的额外 Python 依赖不属于自动打包承诺；把重依赖放入自带 Worker，并按目标平台冻结。
- 发布版本不覆盖同版本不同内容；更新保留启停状态，旧代码仍占用时等待自然退出。

## 实际效果与限制
正常使用公开 v1 的作者不需要因为音乐 / 语音 / Agent 搬家而重做 MOD。这里承诺维护接口与适配，不承诺任意私有 Python 代码、未知第三方依赖或所有未来功能天然兼容。本轮是本地管理中心，不提供联网市场、签名审批或强沙箱。
