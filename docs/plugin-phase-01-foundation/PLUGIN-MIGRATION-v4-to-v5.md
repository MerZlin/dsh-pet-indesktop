# v4 → v5 配置、功能数据与可恢复迁移合同

> **修订：2026-09-27；状态：迁移目标合同，不能把已有局部配置适配当成全量迁移完成。**
>
> [资源基线](PLUGIN-DLC-ARCHITECTURE.md) · [API/贡献合同](PLUGIN-API-CONTRACT.md) · [功能所有者总表](../plugin-roadmap/PLUGIN-FEATURE-DELIVERY-MATRIX.md) · [总路线图](../plugin-roadmap/PLUGIN-DLC-ROADMAP-v5.md)

## 1. 目标和实际基线

保留角色选择、位置、缩放、朝向、透明度、基础交互、角色别名和多实例 `config-slot-N.json`；分离 Core 与各功能配置；保留会话、附件及 keyring 凭据。不能迁移的旧字段保留原始值与 `legacy` 标记，生成成功/跳过/人工处理报告。

Phase 1 已有资源 Registry 与兼容来源，Phase 2 已有插件命名空间及旧扁平字段适配；`config_domains.py` 的 facade 不表示全部领域已迁移。后续 AI/识屏等可选包需要逐域的数据归属、备份、恢复与独立卸载测试。

## 2. 逻辑分层与样板数据边界

```text
受选定安装模式管理的数据根/
  Core 配置与实例配置
  权威安装/启停状态与事务记录
  各功能配置、用户数据、会话/附件索引、缓存、日志
  内容包版本与功能包版本（与用户数据分开）
  备份与迁移报告
安全凭据 → keyring / 安全存储（不是上述目录里的明文 secrets JSON）
```

现有 `config.data["plugins"][plugin_id]` 的 `schema_version/settings/legacy` 是兼容基线，不在本轮直接迁成新的目录树。[屏幕理解最小设计](../plugin-phase-04-updates/PHASE4A-SCREEN-PACKAGE-DESIGN.md)已约定现有应用数据根下 `plugins/official.screen-understanding/` 的版本、`state.json`、实例数据和缓存分层；配置仍沿用每实例插件命名空间，凭据仍在安全存储。此为待实现合同，不立即搬数据；平台绝对路径继续由已有目录解析决定，显式便携标记/只读处理由 Phase 5A 验证。11 个逻辑领域不触发强制改名或批量搬数据。

配置/数据存在不代表包已安装或启用；卸载后保留偏好不得让旧 import 或 fallback 自动复活功能。

## 3. 迁移事务与重复执行

1. 识别旧版本、实例 slot、角色、包配置、会话与附件引用，列清待变更及外部数据。
2. 迁移前生成带版本/时间/来源哈希的备份，敏感存储不导出明文；不覆盖唯一原始数据。
3. staging 中按输入/输出 schema 和幂等标记变换，记录成功、跳过、legacy、人工处理项。
4. 验证后原子切换，重新读取核对角色、实例、配置、会话/附件索引；并发实例先协调写入与持有者。
5. 失败或中断保留报告和备份，恢复上一个一致状态；重试不得重复复制会话/追加数组或覆盖后来修改。

```text
迁移中断 → 确定最后一致状态/恢复旧备份 → 重新执行 → 不重复破坏数据
```

Core 可用旧配置适配或最小资源 fallback 启动；这不等于启用一个未安装的旧功能。用户数据迁移失败不能靠删除数据或静默降级 schema 来通过验收。

## 4. 归属与兼容映射

| 旧数据/能力 | 最终所有者 | 迁移与验收重点 |
|---|---|---|
| 角色选择/别名/档案、位置等 | Core 实例 + 内容 provider | 各 slot 独立；别名无法解析保留原值，资源 fallback 可启动 |
| `festival_reminder_*` 等扁平配置 | 对应现有官方插件 | 保留 ID、旧设置入口的双向兼容与 legacy 原值，不凭领域表重命名 |
| 自动/手动识屏及视觉服务配置 | 屏幕理解包 | 分别解析自动/手动实际使用的服务与凭据，经确认一次性迁移为独立 profile；可无 AI 包配置，之后不再跟随聊天设置 |
| Chat 会话/附件/角色与实例状态 | AI 对话与文件理解包 | 保留内容、顺序、角色/实例隔离和附件引用；关闭写入后迁移，幂等重装，无聊天包不启动会话服务 |
| Provider/API Key/token | 安全存储，按授权消费者使用 | 保留安全引用/授权，不写普通配置、迁移报告、备份明文或 Worker 持久快照 |
| 提醒、台词、音乐、语音、组件等偏好与数据 | 功能总表对应所有者 | 先审计后迁移；停用/卸载默认保留，缓存与个人数据区分 |
| 投喂统计、AI 文件解释记录 | 各自功能所有者 | 模拟投喂和 AI 解释分开；外部原文件不是包数据，绝不改动 |
| 未知旧字段 | 所属 legacy 或未分类原始备份 | 保留且可诊断，不能静默丢弃 |

AI 与屏幕理解可以使用相同服务，但**不能把持续读取聊天配置或聊天凭据引用作为识屏独立运行的前提**。一次性迁移后，视觉 profile 和授权凭据归屏幕理解；不删除聊天原凭据，也不把 Provider 业务搬回 Core。安装 AI 不自动授予截图权限。

### 4.1 自动/手动视觉配置的一次性确认迁移

按 [4A 设计](../plugin-phase-04-updates/PHASE4A-SCREEN-PACKAGE-DESIGN.md)执行，当前仅定义合同：

1. 分别解析旧自动与手动调用链的**实际生效**参数和凭据来源，不能只复制同名字段。保留可能不同的服务、模型和 Key；只有参数与凭据确实相同时才合并 profile。
2. 展示脱敏预览：两条路径将使用哪个服务/模型、是否已配置凭据，以及迁移后与聊天独立。确认前不写入；拒绝或源配置缺失时允许手动配置。
3. 备份非敏感配置与迁移状态，不导出明文 Key，也不记录可推断密钥的对比摘要。安全存储按功能/实例/profile 新建目标条目，保留聊天源条目。
4. 对文件与 keyring 分步写入记录恢复日志，验证绑定和可读性；验证不发起真实模型请求。完成后再提交迁移标记，不能把两种存储假设成天然原子事务。
5. 中断恢复只回退本次未完成写入，不覆盖后来用户手动编辑，不删除其他消费者凭据；重试幂等。已完成后禁止后台再次从聊天配置补值或覆盖独立视觉配置。

### 4.2 可选聊天同步的数据归属

屏幕理解只向已安装启用的 AI 包定向提交有效结果文字；聊天包选择会话、保存问答并提供后续上下文。窗口未打开也可保存，生成中明确返回繁忙，不排队补发。按来源结果与目标去重；手动只同步发起窗口，共享自动按原明确目标集合分别同步，不合并实例会话。

同步成功后的历史属于 AI 包：卸载屏幕理解不删除这些记录，也不迁走全部 Chat 会话。聊天缺失/停用/失败时屏幕理解仍可显示结果，不在 Core 或识屏数据里积累待补发队列。

## 5. Worker 配置与密钥

- `config_push` 仅含非敏感运行摘要，Worker 不读全局 Config、keyring 或完整 Provider/会话数据。
- Core 通过按功能、实例、profile 绑定的 `CredentialVaultPort` 授权单次临时 Key，例如识屏分析；拒绝跨所有者/未授权请求。仅内存使用，完成/失败/取消/超时释放引用，不进入日志、磁盘、普通配置或备份。
- “无敏感配置快照”不等于“禁止所有单次临时凭据”，两者按 [API 合同](PLUGIN-API-CONTRACT.md)区分，保持 Phase 3B 兼容。
- 便携只承诺普通数据/DLC 随目录移动；Key 不明文打包，换机器或账号可能需要重新授权。

## 6. 卸载、重装与跨实例恢复

卸载按照[安装事务](../plugin-phase-04-updates/PLUGIN-UPDATE-PROTOCOL.md)停止任务/Worker、撤销贡献并移除受管理包文件；**默认保留配置、会话和用户数据**。清除数据单独展示范围并确认，不借卸载清除外部文件/工具配置。

多实例共用包时先协调占用；进程内代码或 Windows 文件锁未释放则持久化“待重启完成卸载”，再次启动不得启动其业务，完成文件删除后才标记物理卸载完成。重装使用有效 schema 恢复保留偏好，过旧/损坏数据走迁移/恢复，不重新授予已撤销权限。

包版本回滚与数据 schema 回滚必须协调：若新 schema 不向后兼容，用备份恢复或拒绝不安全回滚，不能只切 `active`。Core 更新保留 DLC、卸载状态和用户数据，不默认装回被用户移除的官方功能。

## 7. 验收与阶段依赖

| 场景 | 必须验证 |
|---|---|
| 正常迁移 | 基础配置、角色别名、每实例、插件命名空间、AI 会话/附件及安全引用保持 |
| 错误/中断 | 坏 JSON、缺包/旧路径、半写入、未知字段、备份恢复、重复执行无破坏 |
| 包生命周期 | 未安装不因遗留配置而执行；卸载保留/显式清除可区分；重装恢复偏好 |
| 依赖独立性 | 屏幕理解无 AI 仍可配置；AI 无识屏/组件仍可用；迁移后修改聊天不影响视觉，不误删源凭据 |
| 视觉迁移 | 自动/手动不同配置、相同配置合并、拒绝迁移、凭据不可读、文件/keyring 半写入、恢复与重复执行 |
| 聊天联动 | 无窗口仍保存；繁忙不插入；来源/目标去重；卸载屏幕包不删 Chat 历史；失败不留补发队列 |
| Worker | 非敏感配置快照、获授权临时请求凭据、旧 generation 无效、日志不含 Key |
| 平台与实例 | 并发占用、普通/便携、只读目录、跨机器重授权；不合并实例会话 |

Phase 4A 必须先盘点样板数据；4B 验证装卸/升级恢复；5A 验证安装模式；5B 迁移 AI 和其余功能；7 做发布实机验收。新合同未通过的项标为待实现，不能以旧测试通过替代。

## 8. 最终效果

以后卸载聊天或识屏时，功能文件和入口消失，但你的偏好/会话默认留下，重装可恢复。Core 只留下通用数据与权限宿主，Worker 通过管道收授权摘要/单次凭据，不直接搬走所有配置。普通安装下的屏幕包分层已写入 4A 设计，显式便携仍待 Phase 5A；当前不会自动迁移你的目录或把密钥打进 ZIP。迁移确认后，视觉与聊天设置彼此独立，但两包启用时仍可同步文字、接着聊天。
