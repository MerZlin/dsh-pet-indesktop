# Phase 7：最小 Core 与官方选装的正式发布验收

> 修订：2026-09-27。**发布前硬门，不要求每个开发提交都先完成三平台实机。第三方生态可以不开放，官方选装不能被内置开关替代。**

## 1. 发布范围与状态必须真实

发布清单引用 [功能交付总表](../plugin-roadmap/PLUGIN-FEATURE-DELIVERY-MATRIX.md)，逐领域标记已交付、当前发布批次与尚未完成项。官方选装是总路线硬目标，阶段版可披露剩余范围，但不能因此宣称整个 v5 可选交付完成。缩减已承诺范围必须重新对齐，不通过把 Phase 5 写成条件项绕过。

最小 Core、Starter 资源与承诺的官方功能包分别形成产物。资源 baseline、进程隔离、运行开关和物理可卸载要有分别对应的证据。

## 2. 三平台与生命周期门

| 范围 | Windows / macOS / Linux 发布前证据 |
|---|---|
| 最小 Core | 离线可见启动、基础交互、窗口/托盘、目录权限、配置与退出，无功能包也可用 |
| 角色资源 | Starter 发现/安装/切换/升级/回滚、损坏降级、最小 fallback |
| 官方功能 | 安装后入口可用，停用无执行，卸载撤销 UI/命令/后台并移除专属文件，重装恢复偏好 |
| Worker | 正常/冻结入口、握手、心跳、请求/响应、超时、有限重启、stale 丢弃、父子退出、授权范围内 fallback |
| 数据与安全 | 多实例隔离/占用、迁移备份/幂等/恢复、会话和附件、单次凭据、密钥不进 ZIP/普通配置 |
| 更新 | Core 不删 DLC/不复装已卸载功能，功能更新不覆盖 Core，自检失败回滚与数据兼容 |
| 交付渠道 | Windows Setup 选装/缺旁置包；各平台 ZIP/对应归档导入与显式便携或明确平台限制 |

特定平台缺能力须明确限制/禁用原因，不把该平台写成全面通过。CI offscreen、受控 HTTP、用户单项手测和真实桌面记录分开；截图/模型付费实测不擅自使用用户凭据。

## 3. 产物与性能门

记录构建环境、命令、样本和实测数字：Core/各功能包及依赖清单、下载和解压体积、冷启动、RSS/CPU、Worker 数量、事件/截图/请求延迟、定时器/线程/磁盘增长、退出和故障恢复成本。

最小 Core 的 import/冻结依赖审计必须证明目标功能的专属代码和依赖确实移除；同一个 EXE 的 Worker 或隐藏菜单不能代替这个证据。沿用有界测试，不擅自追加用户已拒绝的长期 soak。

## 4. 可信发布与维护门

可执行官方包在本地安装就须验证可信来源与完整性；正式对外发布完善签名、公钥轮换/撤销、兼容矩阵、API 弃用、迁移和恢复说明。第三方 SDK/社区 catalog 未启用可标不适用，不能让它们阻塞官方安装体验，也不能借此免除官方执行包的来源信任。

README 提供真实可用的安装/使用说明；发布记录列逐包状态和限制。诊断导出脱敏，不带密钥或截图；每个阶段可独立回滚。门失败就暂停受影响发布，保留已验证 Core 和授权的可用包，不将卸载状态自动恢复成安装。

## 5. 给使用者的效果说明

最终安装包应让你选择“只要桌宠本体”或“加哪些官方功能”。功能自己的 UI、策略、资源和 Worker 在对应包中，Core 通过端口和本机协议连接它们。Setup 可以选装旁置包，ZIP/便携版本可以导入，桌宠扩展管理可以卸载；包文件与个人数据分开，默认保留数据，换机器密钥可能重授权。

不装聊天就没有聊天专属设置，不装识屏就没有识屏入口或截图后台，但角色、动画和基础交互仍可使用。具体安装目录由 Phase 4A/5A 的已验证方案说明。当前这是发布目标，不宣称全部已经实现；第三方生态暂时没有不影响发布，承诺的官方选装未完成则必须明确未完成。
