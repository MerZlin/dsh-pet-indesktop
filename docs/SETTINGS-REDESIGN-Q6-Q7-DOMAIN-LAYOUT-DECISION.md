# 设置重构 Q6/Q7：能力域、布局系统与 UI Skill 评估

日期：2026-09-01  
状态：讨论稿，等待 Q6/Q7 决策，不作为实现规范

## 1. Q6：能力域划分规则

一级侧栏应表示长期稳定的“能力域”，而不是当前页面数量、配置模块、平台或某个控件集合。每个设置只允许有一个主归属；其他页面通过搜索别名或深链提供发现入口，不复制同一个开关。

归属按以下顺序判断：

1. **作用对象**：它改变的是应用生命周期、桌宠实体、人与桌宠的互动、右键菜单、桌面组件、AI 对话，还是外部自动化。
2. **用户意图**：用户会为完成什么任务来找它，而不是代码在哪个模块实现。
3. **能力所有权**：触发位置不等于归属。例如“点击显示余额”属于互动反馈；余额服务配置属于 AI 与对话。
4. **生命周期**：独立开关、独立预览和多个内部设置仍不必自动成为一级页；先判断是否属于已有稳定能力域。
5. **平台差异**：平台是可见性/支持条件，不是能力域。Windows 专属能力不创建“Windows 设置”页。

只有同时满足下列多数条件时，才新增一级能力域：

- 对应独立且长期存在的用户目标；
- 预计至少容纳两个稳定设置组，而非一个功能开关；
- 有独立生命周期、预览对象或数据所有权；
- 放入现有域会让用户难以预测位置；
- 名称不依赖产品内部实现或短期品牌名。

### 建议侧栏（修订版）

| 能力域 | 负责内容 | 明确不负责 | 扩展方向 |
| --- | --- | --- | --- |
| 常规 | 启动、全局窗口行为、系统集成 | 桌宠运动、AI 服务状态 | 托盘、通知、更新等应用级能力 |
| 桌宠 | 形象显示、动画移动、拖拽弹射、碰撞 | 输入命中、菜单外观 | 多宠物、位置规则、动作行为 |
| 互动 | 输入、点击反馈、自言自语、台词绑定 | Provider、Agent 工具连接 | 手势、快捷键、语音等人宠交互 |
| 菜单 | 右键菜单内容、外观、快捷启动、菜单彩蛋 | 所有应用外观 | 菜单命令编排、菜单预览 |
| 桌面组件 | 独立于宠物本体的桌面呈现；当前含“桌面胶囊（灵动岛）” | 桌宠本体、对话窗口 | 状态组件、迷你面板、桌面挂件 |
| AI 与对话 | Provider、模型、视觉能力、生成、对话窗口、用量/服务状态 | 点击触发、主动运行规则 | 多 Provider、会话、记忆与隐私 |
| 自动化与联动 | Agent 联动、主动感知、与其他应用协作 | AI 模型本身、普通输入行为 | 更多 Agent、规则、外部应用集成 |

相较 Q4 初稿，建议做两处改名：

- **“灵动岛”改为“桌面组件”**：灵动岛/桌面胶囊是当前功能名，不足以承载后续迷你状态面板、挂件或其他 overlay。侧栏使用稳定能力域，页内保留产品功能名。
- **“联动”改为“自动化与联动”**：同时容纳外部 Agent 集成和主动感知规则，避免未来再拆出“主动识屏”平台页。

### 设置注册元数据

未来新增功能不应直接向某个页面塞控件。每项设置至少声明：

```text
setting_id
domain_id / group_id
capability_requirement
platform_availability
disclosure_level       # primary | advanced（最多一层）
search_aliases
preview_target
commit_policy          # immediate | on_finish | confirm
```

其中 `domain_id` 使用稳定机器标识，显示名称可以本地化或演进；能力矩阵决定行/组/页是否出现。这样可让搜索、测试、平台差异和后续迁移共享同一来源，而不是由三个平台窗口各自判断。

## 2. Q7：组件与布局分离

不建议让每个设置组件内部同时实现上下、左右、网格和瀑布流。应将稳定的语义组件与可替换的布局容器分开：

- 语义组件：`SettingRow`、`SettingCard`、`SettingsSection`、`PreviewPanel`、`ActionBar`。
- 布局容器：`StackLayout`、`SplitLayout`、`GridLayout`、`FlowLayout`。
- 页面组合：同一个语义组件可以进入不同容器，但标题、说明、状态、控件和可访问性顺序保持一致。

| 布局 | 适用场景 | 收窄后的行为 | 不适用场景 |
| --- | --- | --- | --- |
| 纵向 Stack | 普通设置行、表单；默认布局 | 保持单列 | 大面积实时预览 |
| 左右 Split | 编辑器 + 菜单/桌面组件实时预览 | 预览移到设置区下方 | 普通开关列表 |
| Grid | 同构主题卡、背景图、角色或模板选择 | 减少列数，最终单列 | 标题/说明长度差异大的表单 |
| Flow/Wrap | 标签、小尺寸选项、快捷键 token | 自动换行 | 需要严格列对齐的数据 |
| Masonry | 只读、异构高度的素材/预览画廊，且确有需求时 | 退化为单列 | 设置表单；会破坏扫描顺序和键盘顺序 |

布局切换依据应是**内容区可用宽度 + 字体度量**，而不是操作系统名称或整个窗口宽度。建议先定义 `compact / standard / wide` 三种页面模式；具体断点通过原型和跨平台截图确定，不在讨论阶段写死像素值。

### 字体层级

使用语义 token，不在单个组件硬编码字体家族或字号：

| 角色 | 用途 | 初始建议（逻辑像素） |
| --- | --- | --- |
| `title.page` | 页面标题 | 22–24，Semibold |
| `title.section` | 设置组标题 | 13–14，Semibold |
| `label.primary` | 设置项标题 | 14，Medium |
| `body.secondary` | 设置说明 | 12–13，Regular |
| `caption` | 平台、状态、辅助元数据 | 11–12，Regular |
| `code` | URL、模型 ID、路径 | 12–13，系统等宽字体 |

字号只是原型起点，最终应以 Qt 字体度量、系统缩放和中英文混排截图验证。系统字体和 fallback 由平台主题层负责；颜色、字号、字重和行高由 token 管理。放大字体时，设置行应增高/换行，而不是裁切说明。

## 3. Multica `web-design-guidelines` Skill 是否值得引入

### 结论

**不建议原样引入项目级 skill；建议将其中跨平台原则改写成项目专用的 Qt/PySide6 UI 审查 skill。**

Multica 的 skill 本体只负责在每次审查时拉取 Vercel 的最新规则，再按 `file:line` 输出问题；它不是视觉设计系统或组件布局指南。[Multica skill](https://github.com/multica-ai/multica/blob/main/.agents/skills/web-design-guidelines/SKILL.md)

上游规则明确面向 Web，包含 `aria-label`、语义 HTML、CSS focus、DOM 测量、React hydration、URL state、`Intl` 和浏览器 safe area 等大量内容，直接应用到 Qt Widgets 会产生误报。[Vercel Web Interface Guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md) 上游仓库也说明规则虽有一部分框架无关，但部分专用于 React/Next.js，并采用 MIT License。[Vercel repository](https://github.com/vercel-labs/web-interface-guidelines)

值得保留并转换为 Qt 规则的部分：

- 全流程键盘可操作、清晰且不被遮挡的焦点；
- 命中区域、无交互死区、手势必须有点击/键盘替代；
- 动效尊重 reduced motion、可中断、只在能解释因果时使用；
- 长文本、空状态、极端内容和本地化格式；
- 危险动作确认或可撤销；
- 明确的 hover/pressed/disabled/focus 状态；
- 高信噪比的 `file:line` 审查输出。

项目版 skill 应改为检查：

1. PySide6/Qt Widgets、QSS、菜单和设置页面，而非 DOM/React；
2. Shared UX Contract、稳定能力域和 Menu Action Model；
3. Tab 顺序、快捷键、accessible name/description、焦点恢复和屏幕阅读器；
4. Qt High DPI、系统字体、字体放大、长中文/英文和多屏；
5. `Stack/Split/Grid/Flow` 的适用边界及响应式退化；
6. macOS/Windows/Linux capability matrix，而非平台像素一致；
7. 截图矩阵、视觉回归和 TDD 证据。

此外，不应在每次审查时无版本约束地拉取一份会变化的远端规则。项目版应固定来源版本或把精炼后的规则提交到仓库，更新时通过显式审查，以保证同一提交可重复验证。

## 5. 新增需求：菜单内容编排

### 产品归属

“排序、显示、放入子菜单、提升到根菜单”属于 **菜单 / 内容与布局**，不属于“外观”。它需要和 Q8 已确认的实时菜单预览放在同一个编辑工作区：左侧编辑结构，右侧显示当前平台的真实菜单预览；窄窗口时改为上下排列。

建议“菜单”页分为：

1. 内容与布局
2. 快捷启动
3. 外观
4. 高级配色（高级展开）
5. 彩蛋入口

### 设置页交互

内容编辑器使用树形编排，而不是每个菜单项分别放四个开关：

```text
内容与布局                                      [恢复默认]

☑  AI 对话                           根菜单       ⋮
☑  看看屏幕                          根菜单       ⋮
── 播放 ─────────────────────────────────────────
▾  播放动画                          子菜单       ⋮
   ☑ 待机
   ☑ 转向
   ☑ 移动
☑  切换角色                          根菜单       ⋮
── 工具 ─────────────────────────────────────────
▸  更多工具                          子菜单       ⋮
   ☑ DeepSeek 余额
   ☑ 更新与帮助

[+ 新建子菜单]
```

每一行只承担一组清晰操作：

- 拖拽手柄：调整同级顺序，拖入/拖出子菜单改变层级；
- 显示复选框：用户主动隐藏；
- 名称与图标：来自动作注册表；自建子菜单名称允许编辑；
- 位置标签：显示“根菜单”或所属子菜单，兼作无障碍拖拽的下拉替代；
- 更多菜单：移动到顶部/底部、移动到某个子菜单、提升到根菜单、重命名自建子菜单、恢复该项默认位置。

拖拽不能成为唯一方式。键盘用户必须能通过“移动到……”完成同一操作。

### 推荐层级约束

- 默认最多为“根菜单 → 子菜单 → 动作”两层。原有“播放动画 → 动画类别 → 动画”这类动态集合可以保留系统定义的第二级，不允许用户继续嵌套。
- 普通 leaf action 可以在根菜单和自建/内建子菜单之间移动。
- 动态集合（角色列表、动画列表、快捷启动列表）作为一个不可拆散的 collection action 移动；不能把未知数量的动态子项全部铺到根菜单。
- 空子菜单不渲染；分隔线由相邻可见分组自动生成，用户不直接管理分隔线节点。
- 排序只在同一父节点内有意义；跨父节点移动同时改变层级和顺序。
- 平台不支持的动作不出现在实际菜单中，但在编辑器中保留原位置并标记“此平台不可用”，防止用户在 macOS 保存后破坏 Windows 布局。
- 运行时暂不可用的动作保留位置，可以禁用并解释原因；这与用户主动隐藏是两个状态。

### 必要的安全出口

“桌宠设置”和“退出”目前是恢复配置与终止无托盘桌宠的重要入口。建议：

- 默认固定为可见；允许排序，但不能放入第二级以下；
- 只有检测到系统托盘、Dock 或其他等价入口时，才允许用户隐藏；
- 当一次编辑将最后一个设置入口或退出入口隐藏时阻止保存，并说明恢复方式；
- 设置页始终提供“恢复默认菜单”，同时保留启动时安全模式/配置恢复能力。

### 数据模型

不把标题、回调或平台判断保存到用户配置，只保存对稳定 action ID 的引用树：

```json
{
  "schema_version": 1,
  "template_id": "modern",
  "nodes": [
    {"type": "action", "id": "chat", "visible": true},
    {
      "type": "submenu",
      "id": "user.tools",
      "label": "更多工具",
      "visible": true,
      "children": [
        {"type": "action", "id": "balance", "visible": true},
        {"type": "action", "id": "update_help", "visible": true}
      ]
    },
    {"type": "action", "id": "modern_settings", "visible": true},
    {"type": "action", "id": "quit", "visible": true}
  ]
}
```

代码侧需要一个 `MenuActionRegistry`，每个 action 声明：

```text
action_id
label / icon
kind                    # leaf | collection | system
availability(pet, platform)
enabled_state(pet)
build(parent_menu, pet)
placement_constraints
```

当前模板作为默认树；用户配置保存 override/规范化后的引用树。新增版本动作若不在用户旧布局中，应按模板迁移规则插入建议位置，而不是悄悄丢失；已删除 action ID 在加载时忽略并记录迁移。菜单 builder 只遍历解析后的树，现代/旧版/三平台不再各自硬编码动作顺序。

### 保存与预览语义

该编辑器属于 Q10 的复杂结构编辑：

- 拖拽、显隐和层级调整即时更新右侧预览，但先写入 draft；
- 点击“完成”或离开编辑状态时校验并提交；
- “恢复默认”需要确认，可在提交前撤销；
- 实际右键菜单在提交后下一次打开时使用新结构，不在一个已展开的原生菜单中热重排。

### TDD 准出重点

实现阶段至少覆盖：默认树解析红灯、同级排序、根/子菜单移动、隐藏、动态 collection、平台不可用保留、空容器清理、安全出口、旧配置迁移、实时预览与实际菜单结构一致，以及 macOS 原生菜单实测。Windows/Linux 由共享模型测试和平台 capability fake 覆盖，后续补真实平台截图矩阵。

## 6. 默认菜单树与兜底策略

### 设计目标

默认菜单不是当前硬编码顺序的备份，而是用户首次启动、恢复默认、配置损坏和 schema 迁移失败时共同使用的版本化产品默认值。默认根菜单优先放置高频、可立即执行和用于恢复的动作；状态开关、低频管理动作与工具收进语义子菜单，避免当前菜单过长。

### `modern-default-v1`

```text
[角色头像] 厉害了我的鲸                              [可选彩蛋头部]
────────────────────────────────────────────────────
AI 对话                                             [AI]
看看屏幕                                            [视觉能力]
────────────────────────────────────────────────────
播放动画                                      ›
切换角色                                      ›
播放速率                                      ›
大小                                          ›
────────────────────────────────────────────────────
桌宠控制                                      ›
快捷启动                                      ›      [列表非空]
────────────────────────────────────────────────────
工具与帮助                                    ›      [按能力删减]
Agent 联动                                    ›
主动识屏                                      ›      [Windows + AI]
────────────────────────────────────────────────────
桌宠设置
退出
```

根菜单保持 10–13 个入口；条件项缺失后自动消除相邻重复分隔线。

#### 播放动画

```text
待机 ›
转向 ›
移动 ›
点击回应 ›
随机动作 ›
```

每个类别的动画项按角色资源动态生成。空类别不显示。

#### 切换角色

```text
✓ 当前角色
  其他角色…
────────────────
重命名当前角色…
```

角色列表动态生成并保持单选状态。

#### 播放速率

保持当前 `1.0x–2.0x` 的单选列表；后续可单独讨论是否精简为常用档位。

#### 大小

根据 `catalog.SCALE_STEPS` 动态生成并保持单选状态，不在默认树中展开为多个根节点。

#### 桌宠控制

```text
☑ 拖动物理
☐ 不移动
☐ 鼠标穿透
☑ 窗口置顶
☐ 开机自启
────────────────
回到右下角
隐藏桌宠
生小肥鱼                                      [支持多开时]
```

开关状态来自运行时，不写进布局树；布局树只控制这些 action 的位置和用户可见性。

#### 快捷启动

按用户维护的快捷应用顺序动态生成。列表为空时整个根入口不显示；配置仍保留，新增应用后入口自动恢复。

#### 工具与帮助

```text
DeepSeek 余额                                  [余额能力]
启动 DeepSeek Harness                         [Harness 可用]
打开网页版 DeepSeek
────────────────
检查更新                                      [更新能力]
GitHub 项目页
夸克网盘下载                                  [Windows]
```

这是低频工具集合。建议把当前“更新与帮助”子菜单的叶子提升到这里，避免形成“根菜单 → 工具与帮助 → 更新与帮助 → 动作”的三级路径。

#### Agent 联动

```text
☐ DeepSeek Harness (DSH)
☐ Claude Code
☐ Cursor
☐ OpenCode
────────────────
☐ 开始干活气泡提醒
☑ 任务完成气泡提醒
☐ 过程汇报气泡
```

#### 主动识屏（仅 Windows + AI）

```text
☐ 开启主动识屏
☑ 鼠标穿透时仍允许主动识屏
☑ 触发前先兆提示
☐ 仅当我闲置时触发
☐ dry-run 验证模式
────────────────
打开设置…
```

### 条件删减规则

| 条件 | 默认菜单行为 |
| --- | --- |
| 无 AI 构建 | 隐藏 AI 对话、看看屏幕、余额；保留仍可工作的网页版入口 |
| macOS/Linux | 不创建主动识屏；其用户布局位置仍保存在配置中 |
| 快捷启动为空 | 隐藏整个快捷启动入口 |
| 不支持多开 | 隐藏“生小肥鱼” |
| Agent 能力完全未提供 | 隐藏 Agent 联动 |
| 某动态集合为空 | 隐藏该集合或空类别，不显示空子菜单 |
| 动作运行时暂不可用 | 保持位置并禁用，提供原因；不视为用户隐藏 |

### 固定与可编辑边界

- 彩蛋头部默认显示，但可在“菜单 / 彩蛋入口”关闭；它不参与普通 action 排序。
- 所有普通入口默认允许排序、隐藏、放入用户子菜单或提升到根菜单。
- “桌宠设置”和“退出”默认固定在末组，可在存在等价恢复/退出入口时解锁隐藏；任何时候至少保留一条恢复设置和退出路径。
- 分隔线是组边界的渲染结果，不进入用户配置。
- 自定义布局损坏时不尝试部分猜测渲染：先备份坏配置，加载 `modern-default-v1`，并在设置页显示可恢复提示。

### 现有菜单能力完整性审计

#### 两个迁入设置的理由

1. **AI 设置**：它是持久偏好入口，不是立即执行命令。Q2 已确定新版 Settings System 是唯一能力面；继续保留独立 AI 设置窗口会让保存语义、分类与跨平台能力再次分叉。根菜单保留一个“桌宠设置”，并可从搜索或深链直接进入“AI 与对话”。
2. **切换新版/旧版菜单**：菜单模式本身是低频、持久的菜单偏好，应放在“菜单 / 内容与布局”的顶部。旧版定位为迁移期 fallback，而非与新版长期并列的快捷命令。为避免用户被困在旧版，legacy 菜单在迁移期仍保留“切换到新版菜单”；modern 默认树不再放“切换回旧版菜单”，但可从设置选择旧版。待 legacy 正式退役后删除该设置和兼容 action。

“迁入设置”只改变入口位置，不删除配置或行为。迁移发布说明和首次升级提示必须明确告知新位置；设置搜索应支持“AI 设置 / 旧版菜单 / 切换菜单”等旧称。

### 兜底优先级

```text
有效的用户菜单树
  ↓ 无效 / 不兼容
同 schema 的规范化用户树（忽略失效 action，补必要安全项）
  ↓ 仍无法通过校验
内置 modern-default-v1
  ↓ 打包资源缺失
代码内最小安全菜单：桌宠设置 / 退出
```

默认树必须同时作为打包资源和测试 fixture；最后一级最小安全菜单留在代码中，避免模板资源漏打包后完全失去控制入口。
