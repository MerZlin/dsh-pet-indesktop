# 节日提醒（festival_reminder）PR 报告

> 结论先说：新增一个**默认关闭**的「节日提醒」功能——在你选定的日子（中国节日 / 24 节气 / 西方节日）用桌宠气泡告诉你今天是什么日子，并附一句氛围匹配的文案；可选语音念出来，且与「语音报时」共用一条音频通道，两者撞在同一分钟时**报时自动让位，不会叠音**。

---

## 一、功能亮点

1. **46 个日子，三类可选**：中国节日 14 个（春节、元宵、端午、中秋、重阳、腊八、除夕、元旦、劳动节、儿童节、国庆节…）、24 节气全覆盖、西方节日 8 个（情人节、愚人节、复活节、母亲节、父亲节、万圣节、平安夜、圣诞节）。三类开关独立，可任意组合。
   - **清明节**同时属于「中国节日」和「24 节气」，两个开关**任一打开都会提醒**。
2. **文案随节日氛围走，不是通用祝福**：内置 **314 条**——中文古诗词与名言 199 条（按节日/节气逐条选材）、公有领域西文引文 48 条，另有电影台词 35、游戏台词 22、圣诞歌曲歌词 10。中秋写月与团圆、清明写追思与春景、万圣节只取幽暗夜色不涉惊悚，不会张冠李戴。
3. **提醒时机随你定**：二选一——「按提醒次数」（1–6 次，均匀铺在 09:00–21:00）或「自定义提醒时间」（`09:00, 12:30, 20:00`）。
4. **可选语音播报**：开启后除了气泡还会念出来。音色/语速/音调/音量**沿用「语音报时」的设置**，不必配两套。
5. **与语音报时零冲突**（本次的重点设计）：两者同分钟到点时，**报时让位**；一分钟内只会说一句话，也不会出现两段语音叠在一起。两个功能不依赖"谁先跑"。
6. **随时可看、可听**：
   - 右键菜单 →「今日节日」：立刻查看今天是什么日子
   - 设置页 →「立即试听」：**不用等到节日当天**就能预览效果与声音
   - 右键菜单 →「启用/关闭节日提醒」：一键开关
7. **开机即补**：桌宠不常驻也没关系。若你中午才开机、当天的第一个提醒点已过，会补提醒一次；且**不会压掉当天晚些时候的提醒**。
8. **同一分钟只提醒一次**：靠槽位盖戳幂等，免疫定时器抖动与服务重启。

## 二、使用方式

### 2.1 开启与配置

1. 右键桌宠 → **桌宠设置** → **自动化与联动** 域 → 找到 **「节日提醒」** 卡片。
2. 打开 **「启用节日提醒」**（**默认是关闭的**，需手动开）。
3. 按需勾选 **「中国节日」/「24 节气」/「西方节日」**。
4. 选 **「提醒方式」**：
   - **按提醒次数** → 设 1–6 次，系统均匀铺在 09:00–21:00（1 次→09:00；2 次→09:00/21:00；3 次→09:00/15:00/21:00）。
   - **自定义提醒时间** → 填 `HH:MM`，逗号分隔，如 `09:00, 12:30, 20:00`。留空则回落 09:00。
5. 想听声音就打开 **「语音播报」**（音色等参数在「语音报时」卡片里调）。
6. 想只报节日名、不附文案，关掉 **「附带文案」**。

### 2.2 试听与手动查看

| 想做 | 怎么做 |
|---|---|
| 立刻预览效果（含语音） | 设置页「节日提醒」卡片 → **「立即试听」** |
| 看今天是什么日子 | 右键桌宠 → **「今日节日」** |
| 一键开关 | 右键桌宠 → **「启用节日提醒」/「关闭节日提醒」** |

> 「立即试听」与「今日节日」都**无视总开关**，方便你先试再决定要不要长期开。当天没有节日时会直接告诉你「今天没有特别的节日或节气」。

### 2.3 换成自己的文案

设置页 →「节日提醒」卡片 → **「自定义中文文案」/「自定义西文文案」**，一行一条。自定义内容是**追加**到内置库之后参与轮换，**不会挤掉**内置文案；想加影视/游戏台词等受版权内容，从这里加即可。

## 三、注意事项

1. **默认关闭**。节日提醒属"主动打扰"型功能，升级后不应突然冒出来，因此总开关默认关。
2. **语音播报需要联网**。走微软 edge-tts 在线合成；未安装 `edge-tts` 或断网/代理异常时，**气泡照常显示，只是没有声音**，不会崩溃。合成结果会缓存，同一句不重复联网。
3. **与语音报时的关系**：两者共用同一条音频通道（同一个播放器、同一份缓存目录）。同分钟到点时**报时让位**；若音频通道正忙，节日语音会排队等当前一条播完，**不打断、不叠音**。
4. **内置文案含受版权内容**。电影台词、游戏台词、圣诞歌曲歌词**均在版权保护期内**（中文古诗词与公有领域西文引文不受影响）。`THIRD_PARTY_NOTICES.md` 第 5 节逐作品披露了条数与来源，并给出**三步剥离法**（删三个文件即可得到纯公有领域版本）。再分发或在其他法域发布前请自行评估。
5. **西文库有意不覆盖全部节日**。游戏台词里"广为流传 + 氛围确实契合某节日"的交集远小于电影，宁可缺项也不硬塞弱相关句子；缺口由公有领域库、电影库、歌曲库覆盖。
6. **KJV 圣经的地域差异**：在美国属公有领域，在英国由 Crown letters patent 管理。若在英国分发建议加说明。
7. **农历/节气支持范围**为 1900–2100（`lunar-python` 的数据范围）。
8. **刻意不收录的日子**：政治性纪念日与宗教教义类节日整体不收；**小年**因北方腊月廿三/南方廿四有地域分歧而整体不收；**感恩节**因各库素材均偏弱，按维护者决定整体移除（节日总数 47→46）。
9. **提醒只针对"整日"**：不区分上午/下午场次，一天内按你设的时间点各提醒一次。
10. **本轮未做的验证**：GIF 变体与节日提醒的共存；时区/夏令时切换下的槽位与批次行为。

## 四、技术纪要

### 4.1 分层

| 层 | 文件 | 要点 |
|---|---|---|
| 纯逻辑 | `festival_calendar.py` | 唯一的第三方历法库边界；农历↔公历、24 节气、复活节/第 n 个星期几、除夕 |
| 纯数据 | `festival_data.py` | 46 个节日定义 + 收录策略白名单 |
| 纯逻辑 | `festival.py` | 配置清洗、今日命中、文案挑选、提醒时间、槽位幂等 |
| 纯数据 | `festival_quotes_*.py` ×5 | 314 条文案，按来源分文件 |
| 服务 | `festival_service.py` | 30s tick、气泡落地、启动补提醒、语音委托 |
| UI | `festival_settings.py` | 12 个 `SettingRow`（含试听） |

纯逻辑层**零 Qt**（已纳入 `test_architecture.py` 的机器化守卫）。

### 4.2 几个关键设计决策

- **今日判定用「日期 → 节日」方向**：先算「节日 → 日期」要先解决"农历腊月初八落在哪个公历年"这类跨年归属，容易出错；对给定的一天逐条比对规则没有归属歧义。
- **闰月必须排除**：`lunar-python` 的 `getMonth()` 对闰月返回负数；闰月里的同号日不能被当成农历节日。
- **除夕用「春节 − 1 天」推算**，不直构"腊月三十"——腊月有 29 天的小月年，直构会抛错。
- **槽位幂等**：`reminder_slot` 返回 `YYYY-MM-DDTHH:MM`，服务据此盖戳，同分钟只提醒一次。
- **启动补提醒**：`startup_slot` 返回独立槽位，与正常到点槽位互不压制。

### 4.3 与语音报时的通道共享（本次最核心的改动）

冲突分两层，分别解决：

**播放层** —— 报时服务是进程内**唯一音频通道**，新增公开 API `speak(text)`：

- 通道忙（合成中或正在出声）时不打断也不丢弃，进**深度 1 待播队列**，当前一条播完后自动接上（由 `mediaStatusChanged` 驱动）；
- 只出声不出气泡（`role="speak"` + `_play_only`）——气泡归节日提醒自己管，否则会被 `voice_chime_show_bubble` 二次影响、还会出现两个气泡；
- 共用 `voice_chime_cache`，节日语音同样走缓存去重。

**调度层** —— 两个服务各有独立 QTimer，**谁先触发不确定**，报时先跑时它不会知道节日也要说。故用**注入式让位钩子**而非让节日去"抢"：

```
AppShell.start()
  ├─ _sync_festival_service()      # 先建节日服务（顺序本身是契约）
  └─ _sync_chime_service()
       └─ service.yield_slot = AppShell._chime_should_yield
            └─ FestivalReminderService.should_speak_at(chime_slot)   # 每分钟问一次
```

让位判定**与触发先后完全无关**；让位同样消费槽位（否则本分钟后续 tick 会反复询问并在条件变化时补报）。

**生命周期**：音频通道存在性 = 报时开 **OR**（节日开 AND 节日语音开）。报时关闭但节日语音开启时通道必须仍存在，否则节日播报会静默失效——这是最隐蔽的接线坑，已用测试锁死。

### 4.4 第三方历法库的许可决策

| 库 | 许可证 | 结论 |
|---|---|---|
| `lunardate` / `zhdate` | GPL-3.0-or-later | ❌ 与本项目 MIT 不兼容，**不可引入** |
| **`lunar-python`** | **MIT** | ✅ 采用 |

`lunardate`/`zhdate` 同源于 1988 年 Fung F. Lee / Ricky Yeung 的 GPLv2 `lunar` 项目，其数据表被广泛转载，抄进 MIT 项目会造成 copyleft 传染。**这条已写进 `requirements.txt` 注释，防止后人"顺手换回去"。** `lunar-python` 为 MIT、纯 Python、无数据文件、无传递依赖，PyInstaller 静态可收集（无需 `--collect-all`）。

### 4.5 受版权文案的「可剥离」设计

三类受版权文案各自独立成文件，`festival.py` 用**真实 `import` 语句包在 `try/except ImportError`** 里导入：

- 为什么不用 `importlib` 动态导入：**PyInstaller 只对字节码里的 import 语句做静态分析**，动态导入的模块不会进包、打包后必崩；
- 为什么用 `try/except`：删文件即降级为空表，不需要改其它代码就能得到纯公有领域版本。

出处**以行内注释紧跟每条文案**，而不是集中在 docstring 列清单——集中清单会随增删悄悄漂移，而它要用于第三方版权声明。

### 4.8 本次修复的真实缺陷

1. **让位判定依赖生命周期顺序**（端到端用例抓红）：`should_speak_at` 读构造期缓存的配置，而服务构造后仍是默认值。用户若恰好在节假日整点启动，报时首次 tick 可能早于节日服务配置落地，导致**两个功能同时出声**。已改为每次现读配置，并把 `AppShell.start()` 里的节日同步提到报时之前。
2. **第三方声明两处错数**（Forrest Gump 2/3、Home Alone 3/2）：一增一减总数恰好不变，只看总数发现不了。已修正并把该比对**固化为测试**。
3. **Ubuntu CI 因 `libpulse` 红过一次**：两个新用例为取 `QMediaPlayer.MediaStatus` 枚举，在测试里导入了 `QtMultimedia`——Linux 上该导入连带加载 libpulse，CI 未装。已修：终止态枚举改由 `_ensure_player()` 缓存，**回调不再有任何 Qt 导入**；测试改用哨兵值。**本机是 Windows，三道本地门发现不了这类平台缺口。**
4. `yield_slot` 属性缺失时 tick 抛异常 → `getattr` 兜底。

## 六、风险与回滚

| 风险 | 缓解 |
|---|---|
| 受版权内容合规 | 三个模块物理隔离，删文件即剥离；声明已逐作品披露 |

| 行数预算 | `window.py` 未改动；`modern_settings_dialog.py` 按实测校准 2270→2272 |

**回滚**：总开关默认关闭，一键可停；删除 10 个新增源码文件 + 回退 15 个修改文件的 diff 即可完全回滚，不污染既有链路。
