- 日期：2026-08-21
- 任务：为现有 PySide6 桌宠增加可配置、多 Provider、流式、多轮上下文的 AI 对话能力
- 实际开发目录：`E:\AI\test\Gametest\dsh-pet-standalone`

## 已确认决策

- 实现完整可运行版本，而不是只提供架构草图。
- 首期支持多个 OpenAI Chat Completions 兼容 Provider；不实现 Gemini 原生协议。
- 保存 JSON 会话，支持恢复、清空、失败重试和停止生成。
- 使用独立聊天窗口；桌宠通过状态、短气泡和可选动作联动，不改透明 mask/动画状态机核心。
- 使用标准库 HTTP + QThread；API Key 优先系统钥匙串，失败时允许配置文件回退。
- system prompt 优先级固定为：当前角色用户覆盖 > 角色 manifest > 全局默认。
- 上下文使用消息数和字符数双重裁剪；角色切换时隔离上下文。
- 本轮只创建和修改 `modern/ai-chat`，不执行 `git add`、`git commit`、`git push`。

## 2026-08-26：新版聊天窄屏、错误态与附件交互修复

### 根因与修复

- 窄屏抽屉遮罩出现白色断层，是因为抽屉仍保留桌面端 `238px` 固定宽度，而遮罩按响应式计算的 `286px` 起点布局。紧凑模式现在先更新抽屉实际固定宽度，再以实际几何边界定位遮罩；切回桌面布局时恢复 `238px`。
- 请求失败内容此前只给整个消息行设置浅红背景，状态和重试按钮又分别占行，缺少独立层级。现在错误正文使用带细边框和圆角的独立错误卡片，失败状态与重试操作收进同一水平操作行。
- 输入框自身接受 URL 拖放，导致 Qt 默认把本地文件写成 `file://` 文本。新增附件输入组件，在输入框层拦截本地 URL 并转交附件列表；图片显示缩略图，其他文件显示类型图标，悬停时右上角显示删除按钮。
- 助手消息只配置了最大宽度且使用 `Maximum` 尺寸策略，布局会按文本首选宽度提前换行。现在助手行使用扩展策略，并监听消息视口尺寸变化，按可用正文宽度更新固定范围；用户气泡仍保持内容自适应和最大宽度限制。
- 状态与模型信息从侧栏底部移到主内容标题栏“快速模式”右侧，显示绿色状态点、“就绪/生成中”和当前模型名；侧栏底部只保留“跟随桌宠”。

## 2026-08-26：流式输出、空响应与菜单事件循环修复

### 根因与实现

- 会话“重命名”原图标只有三条斜线，在 16px 原生菜单槽内近似弯钩，语义不清。改为“文档 + 铅笔”组合图标；删除项改用垃圾桶图标，置顶继续使用图钉。
- Provider 可以在没有异常、也没有任何正文分片时正常结束，旧逻辑会保存空 assistant 消息并留下只有复制按钮的空白回复。工作线程现在把空白结果转换为明确失败；窗口完成回调另有一次防御校验，统一显示“模型未返回任何内容，请稍后重试或检查模型配置”。网络异常与读取超时继续进入同一错误卡片和重试入口。
- 单次 SSE 分片可能包含大段正文，旧实现会在 GUI 线程一次性设置全部文本并直接滚至末尾，用户会错过回复开头。新版将网络分片写入缓冲区，由 18ms GUI 定时器自适应取出少量字符，形成稳定打字机效果；消息高度增长时滚动条在下一布局周期持续跟随。
- `QScrollBar.maximum()` 在消息布局刚变化时仍可能是旧值，立即设置到底部会失效。滚动现在先立即定位，再在下一个事件周期按更新后的范围二次定位。
- 点击 AI 对话时，窗口构造发生在 `QMenu.exec()` 的嵌套事件循环内，加载会话和构建复杂控件会阻塞原生菜单，因此表现为延迟或偶尔无法显示。现在先等待弹出菜单完全关闭，再创建聊天窗口，且同一窗口只保留一个待执行打开任务。
- “退出”此前也在菜单嵌套事件循环内直接调用 `QApplication.quit()`；macOS 原生菜单跟踪未退出时，外层退出事件可能不生效。现在显式关闭活动菜单，并在下一 GUI 事件周期调用退出。

### 测试

- 新增回归测试覆盖空 Provider 响应、打字机缓冲完成顺序、重型聊天窗口延迟创建，以及关闭活动菜单后退出。
- 完整回归：`129 passed`，包含本地 Provider HTTP 连接测试。

## 2026-08-26：严重问题复修——内容高度与原生菜单回调

### 为什么上一版仍会偶现

- 上一版依赖 `QApplication.activePopupWidget()` 判断右键菜单是否已经关闭；macOS 原生 `NSMenu` 处于跟踪状态时该接口可能返回 `None`，所以 AI 窗口仍可能在 `QMenu.exec()` 的嵌套事件循环中同步构造，退出回调也可能过早进入错误的事件循环。
- 对话滚动区在主布局中使用纵向 stretch，短对话也会强制占满标题栏与输入卡之间的全部可用高度；尾部空白不是消息自身 margin，而是滚动视口被强制扩展。

### 最终实现

- 所有标记为 `closeOnTrigger` 的桌宠菜单动作，在菜单可见时只记录回调并关闭根菜单；`PetWindow._show_context_menu()` 等 `QMenu.exec()` 真正返回、清除活动菜单引用后，再逐一执行打开窗口、退出、外部工具等动作。
- 隐藏菜单上的程序化 `QAction.trigger()` 仍立即执行，保持现有单元测试、快捷入口及非交互调用行为兼容。
- 对话滚动区改为固定策略下的动态高度：短内容按消息布局 `sizeHint` 自适应；内容超过标题栏与输入卡之间的可用空间后才扩展到上限并启用滚动。
- 消息新增、空状态切换、窗口缩放和打字机输出期间都会重新计算内容高度，保留适当的上下内边距，不再出现回复底部到输入框之间的大块空白。

### 红绿测试与验证

- 修复前新增 3 项回归测试：短对话实测尾部空白 `397px`、菜单关闭型回调未在 `exec()` 返回后派发、关闭型 QAction 在菜单可见时直接执行；结果为 `3 failed`。
- 实现后相同测试为 `3 passed`；桌宠功能专项 `58 passed`。
- 离屏渲染 `1180×720` 确认输入卡紧跟消息内容且留白合理。
- 最终完整回归：`132 passed`，包含本地 Provider HTTP 连接测试。

## 2026-08-26：输入区状态布局、最小化恢复与单击退出

### 根因复盘

- 对话区只有一种纵向布局策略，无法同时满足“空会话输入框居中”和“有消息后输入框固定到底部”。短回复若让滚动区自然收缩，输入框会停在窗口中部；若让滚动区始终扩展，消息又会贴在顶部并在回复与输入框之间留下大块空白。
- AI Chat 最小化后，窗口实例仍存在且 `isVisible()` 仍可能不能反映用户可见状态；`show()`、`raise_()` 和 `activateWindow()` 都不会清除 `WindowMinimized`，因此菜单回调看似成功但窗口没有恢复。
- 上一轮用 `activePopupWidget()` 轮询来规避原生菜单嵌套事件循环，只能作为托盘或非桌宠菜单入口的兜底。macOS 原生菜单不保证被该 Qt API 识别，确定性方案仍应是等待 `QMenu.exec()` 返回后派发动作。
- 退出动作已经改为在 `QMenu.exec()` 返回后执行，但仍无条件使用零延迟定时器，第一次点击可能只结束菜单交互而退出回调未及时执行。

### 最终实现

- 空会话使用上下弹性空间，将空态提示与输入卡作为一个紧凑组合居中；第一条消息创建后收起外层弹性空间，消息视口占据剩余高度，输入卡固定在底部。
- 消息时间线顶部使用弹性空间：短会话从底部向上生长，最后一条回复紧邻输入卡；内容超过消息视口后弹性空间自动收缩为零，此时才出现纵向滚动。聊天时间线明确禁用横向滚动。
- 呈现已有聊天窗口时检测 `isMinimized()`；最小化窗口调用 `showNormal()`，普通隐藏窗口继续调用 `show()`，随后再执行置前和激活。
- 退出回调发现活动菜单仍存在时，先关闭菜单并延后一拍退出；正常桌宠右键菜单已返回时直接调用 `QApplication.quit()`，避免首次点击被吞。菜单后的确定性回调队列是主方案，popup 轮询仅保留为其他入口的兼容兜底。

### 红绿测试与视觉验证

- 修复前新增 3 项回归测试，分别复现有消息后输入卡未固定到底部、最小化窗口无法恢复，以及菜单已返回后退出仍被延迟，结果为 `3 failed`；实现后全部转绿。
- 追加空会话组合居中和长内容溢出两项边界测试，覆盖“无无意义滚动条”和“只有内容超高才纵向滚动”。
- 离屏渲染空会话、短会话和长会话三种 `1180×720` 状态：空态居中，短回复与输入卡间距稳定，长内容出现纵向滚动且无横向滚动条。
- 最终完整回归：`137 passed`，包含本地 Provider HTTP 连接测试。

## 2026-08-26：错误卡视觉恢复与消息流方向修正

### 改进内容

- 上一轮将消息时间线的弹性空间放在首项，虽然缩短了最后回复到输入框的距离，却把所有短消息整体推到视口底部，不符合标准聊天应用“从顶部向下阅读”的信息流。现在弹性空间移到消息列表末尾：消息始终从标题栏下方开始向下排列，输入卡继续固定在窗口底部，只有内容超过视口后才出现纵向滚动。
- 错误卡此前依赖 QSS `padding` 给内部布局留白，Qt 的布局盒模型没有稳定地把这部分空间应用到子控件，因此出现正文贴边、重试按钮挤压边框；普通消息复制栏也仍显示在卡片外，形成视觉回退。
- 错误态现在由组件逻辑设置明确的四边布局边距，错误正文、“本次回复未保存”和重试按钮全部位于同一个圆角浅红卡片内；错误/生成状态隐藏普通复制工具栏，恢复正常状态时再显示。

### 验证

- 回归测试先复现顶部消息被推至 `323px` 位置、错误态复制栏仍显示和错误布局边距为零，修复后全部通过。
- 离屏渲染 `1180×720` 的短会话与错误会话：短消息从时间线顶部向下排列；错误卡内边距、边框、状态和操作按钮层级恢复正常。
- 最终完整回归：`137 passed`。
