# 右键菜单图标调研与双模板重构记录

日期：2026-08-25

## 问题与目标

- “生小肥鱼”使用角色头像后，该行被 32px 非方形位图撑高，图标与文字的视觉中心不一致。
- 旧菜单将动画、窗口状态、设置、工具混在一个长列表里，扫描成本较高。
- 原有 `QStyle.StandardPixmap` 图标来自不同系统语义：例如复位显示成扫帚、角色显示成文件夹、拖动物理显示成绿色勾，虽然“有图标”，但不能稳定表达功能。
- 需要保留旧版作为默认，同时允许用户在新旧菜单间往返切换。

## 调研结论

### 图标尺寸与对齐

Qt 提供 `QStyle.PM_SmallIconSize` 作为当前平台的小图标尺寸。Windows MenuFlyout 指南给出的菜单图标标准尺寸是 16×16px，并建议使用可缩放的符号/矢量图标。结论是菜单头像不能硬编码为 32px，必须按平台度量创建方形画布，再在其中做光学居中。

### 图标使用范围

Apple HIG 和 Windows 菜单指南都强调：

- 只为高频、标准或能清楚表达的命令使用图标。
- 相似命令组使用一个引导图标，不要给每个相似条目重复相同图标。
- 含义模糊的图标会增加视觉噪声，宁可不显示。

因此动画分类的入口使用播放图标，具体动画名称不重复放图标；新版顶层只为主要功能和功能组显示图标。

### 分组与层级

Apple 建议高频命令靠前、相关命令放在同一分组、长菜单拆分为子菜单，同时限制子菜单深度。桌宠动画属于动态且可能很长的用户内容，因此允许“播放动画 → 分类 → 动画名”的例外层级；窗口快捷开关仍保留在顶层，避免高频操作被埋藏。

调研来源：

- [Apple Human Interface Guidelines — Menus](https://developer.apple.com/design/human-interface-guidelines/menus)
- [Qt QStyle — PM_SmallIconSize](https://doc.qt.io/qt-6/qstyle.html)
- [Microsoft — Icons in Windows apps](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/icons)
- [Microsoft — Menu flyout and menu bar](https://learn.microsoft.com/en-us/windows/apps/develop/ui/controls/menus)

## 模板设计

模板文件：

- `pet/menu_templates/legacy.json`
- `pet/menu_templates/modern.json`

配置项 `context_menu_template` 默认是 `legacy`。JSON 分别描述两版分组和顺序；`pet/context_menu.py` 只负责模板加载与分发，具体布局分别由 `pet/context_menus/legacy.py` 和 `pet/context_menus/modern.py` 构建。稳定的叶子动作与图标绘制放在 shared/icons 文件中，不在两个布局文件间互相导入。

### 旧版模板

保留原生 Qt/macOS 菜单外观、原有扁平结构和无装饰图标的动作样式；只有“生小肥鱼”保留角色头像。仅保留必要的功能变化：“生小肥鱼”放到“开机自启”下方，Harness 下增加网页版 DeepSeek，并在退出前提供模板切换。

```text
AI / 设置
────────
五个动画分类 / 速率 / 拖动物理 / 角色
────────
窗口与启动选项 / 开机自启 / 生小肥鱼 / 大小
────────
Harness / 网页版 DeepSeek
────────
切换到新版菜单
────────
退出
```

### 新版模板

```text
AI 对话
────────
播放动画 > 分类 > 动画
切换角色 >
────────
播放速率 >
大小 >
拖动物理 / 回到右下角 / 不移动 / 窗口置顶

────────

打开网页版 DeepSeek
────────

────────
```

新版共有交互、播放、功能、工具、桌宠设置、模板、退出七个逻辑分组，使用浅灰 1px 横线表达分组。“功能”的八项和“工具”的两项直接位于一级菜单；只有必须继续选择具体值的播放动画、角色、播放速率和大小保留子菜单。布尔开关和单选值在启用时于右侧显示蓝色圆形勾，左侧语义图标保持不变。

## 新旧设置窗口隔离

旧版菜单继续打开原始 `PetSettingsDialog`，只提供动作等待和自言自语配置，避免旧版操作路径随新版变化。

新版菜单打开独立的 `ModernSettingsDialog`。窗口参考 Modern/Otty 的 macOS 设置应用，采用左侧分类、搜索框和右侧标题+圆角卡片布局：

1. 常规：在同一滚动页中放置“外观与窗口”“动画行为”“自言自语”三张分区卡片。
2. AI 设置：使用“模型与连接”“生成参数”两张卡片，包含 Provider、API、模型、Key、System Prompt、生成参数和测试连接。

每个设置行左侧是 14px/600 的标题和 12px/400 的灰色说明，右侧是唯一操作组件；页面标题为 26px/600。新版侧栏、菜单和正文优先使用 macOS 系统字体（SF Pro Text），中文由 PingFang SC 回退。

### 浏览器控件视觉目标

新版设置先定义 `BROWSER_CONTROL_SPEC`，再由统一样式实现：

- 单行输入、下拉和数字框目标高度 32px，白色背景、1px `#cfd4da` 边框、7px 圆角和 8px 水平内边距。
- hover 边框使用 `#aeb6c0`；focus 使用 2px `#0a84ff` 聚焦环，接近 Chromium/Safari 表单反馈。
- 数字框保留右侧独立步进区，并自绘上下 chevron，避免 Qt 样式表覆盖后箭头消失。
- 滚动条宽 8px，轨道透明，滑块 4px 圆角；hover 时加深。
- 搜索会匹配设置标题、说明和内部标识，自动切换常规/AI 页、滚动到目标并高亮。Enter 在多个结果间循环，不再触发默认保存按钮关闭窗口。

无 Chat 构建不会创建 AI 设置侧栏页。

## 开发过程

1. 先添加模板默认值、双向切换、现代菜单结构、头像尺寸和三 Tab 保存测试；旧代码下 4 项测试失败。
2. 新增 JSON 模板包和统一 `pet/context_menu.py` 渲染器。
3. 使用 `PM_SmallIconSize` 创建方形头像画布，并做轻微的垂直光学校正。
4. 用统一的 QPainter 线性图标替换语义不匹配的系统 StandardPixmap。
5. 将桌宠设置窗口重构为三 Tab 控制中心，保存后由现有窗口即时刷新入口应用。
6. 为 Windows PowerShell、本地 macOS 脚本和 GitHub macOS workflow 增加模板 JSON 打包数据。
7. 第二轮发现统一渲染器和统一设置回调仍会造成版本串改；先增加模块隔离、旧版回调、新版七分组、侧栏面板和 Retina 头像测试。
8. 将统一渲染器缩减为 dispatcher，新旧布局拆为独立模块；恢复旧版设置对话框并新增现代侧栏设置面板。
9. 将“功能”的八项和“工具”的两项固定在新版模块，新增网页版 DeepSeek 入口。
10. 第三轮以 Modern 用户菜单和 Modern/Otty 设置截图为视觉基准，补充菜单视觉、新版一级功能和“常规 / AI 设置”卡片层级测试。
11. 新版菜单使用 15px/500 系统字体、17px 灰色线性图标、约 27px 行高、14px 外圆角、8px 选中圆角和组间细分隔线。
12. 新版设置改为 230px 侧栏、搜索框、26px 页面标题、分区标题和 12px 圆角卡片；复选框替换为自绘 macOS 风格开关。
13. 第四轮按版本拆分样式：`menu_styles/legacy.py` 恢复旧版原生外观，`menu_styles/modern.py` 只服务新版，字体/颜色与子菜单继承放在 `menu_styles/common.py`。
14. 第五轮确认 Modern 用户账户菜单并不适合作为桌宠菜单基准，改用 macOS 项目弹出菜单截图：纯白背景、`#d2d2d2` 细边框、12px 外圆角、14px 常规系统字体、18px 深灰描边图标、约 30px 菜单项和浅灰圆角选中块。
15. 移除新版组间可见横线，以 6px 留白维持分类层级；齿轮、仪表盘、弹跳物理、终端、网页、模板等图标重新绘制为统一描边语言。“生小肥鱼”在新版使用鱼形语义图标，旧版仍保留角色头像，不产生跨版本视觉串改。
16. 第六轮根据实机对比恢复 `#e5e5e5` 细分隔线，将菜单项左内边距从 34px 收紧到 16px，使图标与文字间隔接近参考图。
17. 新版不复用原生左侧勾选区，而为所有 checkable action 安装独立右侧蓝色圆形勾；状态随 `toggled` 信号即时变化，子菜单中的角色、速率和大小选项同样适用。
18. QSS 的 `0.5px` 菜单边框会在 Qt/macOS 尺寸计算中触发崩溃，因此改为无 QSS 边框，再用透明覆盖层按 `1 / devicePixelRatio` 绘制真正的一物理像素 hairline。弹出菜单的最终宽度在 `aboutToShow` 后才稳定，边框和右侧勾需延迟一个事件循环定位。
19. 第七轮新增新版首行趣味入口：28px 圆形 `ojingjing.jpg`、标题“厉害了我的鲸”、右侧自绘鼠标指针和“请点击”。入口由独立 `QWidgetAction` 实现，不侵入旧版 `QAction` 布局。
20. 每次点击创建一个新的 `FramelessWindowHint` 图片窗并以 24px 偏移堆叠；窗口完整等比显示图片，内部提供“关闭 / 全部关闭”。窗口管理器持有所有实例，单窗关闭时主动注销，避免 Python 包装对象提前释放。
21. 新版字体从 14px 收到 13px，菜单项左内边距从 16px 收到 13px。旧版“生小肥鱼”不再显示头像；新版恢复经过 DPR 和内容居中处理的角色头像。
22. 子菜单状态勾曾在所属菜单隐藏时被提前 `show()`，因此以默认坐标出现在左侧。现在隐藏菜单内的状态层始终隐藏，`aboutToShow` 后按最终 action geometry 定位，`aboutToHide` 时全部清理；仅当前可见菜单中的已选项显示蓝色勾。
23. 第八轮将菜单项高度从约 26px 收到约 22px、首行从 42px 收到 36px、分隔线外边距从 5px 收到 3px；离屏菜单高度从 560px 降至 451px。子菜单箭头右边距由 5px 增至 10px，避免过度贴边。
24. 首行固定头像迁移到 `assets/big_blue_fat_fish/ojingjing.jpg`；弹窗每次从该目录支持的 JPG/PNG/WebP/BMP 文件中随机选择，macOS、Windows 和 CI 打包均改为收录整个目录。
25. 图片窗由 `Qt.Tool` 改成普通无边框 `Qt.Window`，避免 macOS 在应用失活时自动隐藏 Tool Window；实现整窗左键拖拽。管理器新增 `restore_all()`，重新点击首行时先恢复已有窗口再创建新窗口，点击桌宠时只恢复已有窗口。
26. 第九轮先用 `QStyle::styleHint` 实测 macOS：普通子菜单弹出延时仅 100ms，真正造成同级切换停顿的是 `SH_Menu_SubMenuSloppyCloseTimeout=1000ms` 的菜单路径保护。公有样式新增 `ResponsiveMenuStyle`，递归安装到新旧菜单及全部子菜单；保留菜单路径保护，但将关闭等待缩短到 120ms、弹出延时缩短到 60ms，并允许悬停立即选中同级 action。

34. 第十一轮按 Modern 侧栏继续校正：侧栏项固定 34px，增加独立 hover 底色、9px 圆角和更稳定的图标/文字内边距；选中态不再依赖平台原生 QListView 尺寸计算。
35. 重写纵向 `SettingRow` 的布局树，标题与说明直接以 2px 视觉间距排列，再以 7px 间距连接多行输入或快捷应用组件；移除曾把标题区与控件区各分一半剩余高度的 stretch，修复候选内容、System Prompt 和快捷启动说明的大块空白。

37. WebM Chat 失焦消失并非解码器停帧，而是 macOS 对 `Qt.Tool` 的窗口管理：accessory 应用失去激活时 Cocoa 会隐藏 Tool Window。此前 `WA_MacAlwaysShowToolWindow` 被错误绑定到“窗口置顶”。现在桌宠在 macOS 上始终启用失焦可见属性；置顶开关只控制 `WindowStaysOnTopHint` 和原生 NSWindow level，关闭置顶也不会隐藏窗口。
14. 将旧版生小肥鱼移到开机自启后，并为新旧版都补充网页版 DeepSeek；实现浏览器风格字段、数字步进器、滚动条和真实搜索定位。

## 踩坑与处理

### 不能用请求尺寸代替平台菜单尺寸

`pet.icon_pixmap(32)` 返回的是角色内容缩放结果，并不等于系统菜单希望显示的图标尺寸。macOS 菜单因此增高单独一行。现在先读取 `PM_SmallIconSize`，再生成同宽高 QIcon。

### QIcon 方形不等于内容视觉居中

角色本身是窄高构图，只把图片放进方形画布仍可能显得偏低。实现中按内容尺寸居中并做轻微光学校正，且不改变其他菜单行高。

### Retina DPR 会让头像再次缩小

角色帧可能携带 `devicePixelRatio=2`。旧修复使用点坐标直接绘制源 QPixmap，Qt 会再次按逻辑尺寸除以 DPR，导致 16px 图标槽里的角色只剩约一半。现在先规范化源图 DPR，再使用明确的源/目标矩形缩放；测试使用 Retina 源复现并检查非透明内容占满至少 80% 高度、水平中心误差不超过 1px。

### 共享设置回调会破坏旧版 UI

模板 JSON 虽然分开，但两版都调用 `on_open_settings`，仍然等同于共享 UI 行为。现在窗口暴露 `on_open_legacy_settings` 与 `on_open_modern_settings` 两个入口，旧版表单和新版侧栏面板的生命周期也分别管理。

### 原生 QMenu 与参考图的密度不同

只设置字体会继续使用平台默认行内边距，图标、分隔线和选中态无法形成统一层级；过大的上下 padding 又会让长菜单在小屏上自动分栏。新版最终使用 20px 最小内容高度加 4px 上下 padding和 1px 行外间距，形成约 30px 逻辑行高。旧版不使用这套规则，继续交给平台原生样式计算。

### 视觉共享不等于版本共享

上一轮把 Modern 风格直接施加到 dispatcher，虽然布局代码分开，旧版视觉仍被新版影响。现在 dispatcher 先识别模板，再分别调用 legacy/modern style；通用文件只保存字体、颜色 token 和子菜单样式继承，不包含任何版本布局或具体样式表。

### 字体族不能只写死一个英文名称

SF Pro Text 不一定在 Qt 的非 macOS 测试环境中以该名称注册。代码先使用 `QFontDatabase` 获取系统通用字体，样式再按 SF Pro Text、Apple 系统字体、PingFang SC 的顺序声明，确保 macOS 中文不会回退到视觉不一致的通用 Sans Serif。

### StandardPixmap 跨平台语义不稳定

Qt 标准图标的目标是平台控件语义，不是本项目业务语义。同一个枚举在 macOS 上可能呈现为彩色旧式图标。新版改用自己的线性绘制函数，但颜色来自当前菜单 palette，避免固定黑色在深色模式下不可见。

### JSON 在源码可读，不代表打包后可读

PyInstaller 不会因为 Python 使用 `importlib.resources` 就自动携带任意 JSON。三个构建入口均显式增加 `pet/menu_templates` 数据目录。

### 设置保存不应无条件触碰系统自启

控制中心加入开机自启后，如果每次保存都调用系统写入函数，会在只修改动画时也重写 LaunchAgent/注册表。现在只有状态相对打开窗口时发生变化才调用。

### 子菜单卡顿不是动画或业务回调阻塞

Qt/macOS 默认会在鼠标朝已展开子菜单方向移动时启用“sloppy submenu”路径保护。实测普通弹出延时只有 100ms，但路径保护关闭超时为 1000ms；从“播放动画”直接滑到“切换角色”时，旧子菜单因此继续占有悬停选择，表现为 1–2 秒后才切换。修复放在公有 `QProxyStyle` 中并递归覆盖所有菜单层级，使旧版原生外观和新版自定义外观共享响应策略而不共享布局样式。

1. 动作头像再次变小的根因不是 DPR，而是异步解码返回了完整 640×360 视频帧；其中角色只占很小区域。`fitted_pet_pixmap_icon()` 现在先按 alpha 裁掉透明画布，再按比例填满 18px 原生槽，所有角色类菜单图标共用这一防回归入口。

## 2026-08-25 第十七轮：首轮长菜单稳定性、失焦置顶与 hover 主线程治理

### 实施计划与过程

1. 先增加“可见子菜单禁止缩略图重排”“后台任务有界派发”“菜单关闭后恢复置顶”“关闭置顶时不错误提升”四组失败测试。
2. 分析首轮与第二轮随机动作菜单的差异，逐一排查后台解码、GUI 信号回调、QAction 变更和 QMenu 滚动布局。
3. 把动画任务从一次性全量投递改为最多两个活跃任务的续派队列，并将可见期图标更新延迟到安全的菜单生命周期。
4. 将菜单关闭和应用激活状态变化纳入 macOS 原生窗口层级恢复路径，同时保持不激活窗口、不抢输入焦点。

### 开发记录

1. 首轮随机动作菜单异常、第二轮正常的根因，是第一轮后台代表帧陆续完成后，GUI 线程对正在显示且可滚动的 QMenu 连续执行几十次 `QAction.setIcon()`。每次 ActionChanged 都会让 Qt 重新计算菜单 sizeHint、滚动偏移和动作几何，最终出现圆角边框在“哈欠连天”附近结束、后续动作继续绘制的堆叠现象。第二轮所有图标已缓存，显示前布局一次完成，所以看起来正常。
2. 现在子菜单可见期间只解码和写入线程安全的 `QImage` 缓存，不修改 QAction。未缓存项保持尺寸完全一致的加载占位；子菜单隐藏后或下一次 `aboutToShow`、Qt 尚未布局前，再批量使用缓存头像，因此第一轮滚动几何保持不变。
3. 旧实现 hover 到“随机动作”时会立即创建并向 QThreadPool 投递约 80 个 QObject/QRunnable；即使线程池只执行两个，GUI 线程仍承担全部对象创建、信号连接和后续图标回调。现在待处理项保存在轻量队列中，任意时刻最多构造并保留两个 worker，完成一个才续派一个。
4. 点击其他应用后启用置顶的桌宠被压到后方，是 Cocoa 在关闭原生菜单和应用 activation policy 转换时重新排序其 owner Tool window，而窗口 level 只在 show/切换置顶时设置。现在根菜单 `aboutToHide` 和 `applicationStateChanged` 都会异步重新提交当前 NSWindow 的 floating level；关闭置顶时不会执行该路径，也不会调用 `activateWindow()`。
5. GUI 线程审计确认视频读取、代表帧选择和缓存写入都在 worker；hover 路径只做字典查询和至多两个任务的创建。图像到 QPixmap 的转换与 QAction 更新仅在菜单不可见的安全阶段执行。

### 踩坑点

- “解码已放后台”并不等于 GUI 不阻塞；worker 的完成槽仍在 GUI 线程运行，槽内 `setIcon()` 引发的级联布局才是本轮真正的卡顿来源。
- QThreadPool 的 `maxThreadCount=2` 只限制同时执行数，不限制调用 `start()` 时创建和排队的 QRunnable 数量；长列表必须自行做有界续派。
- macOS `WindowStaysOnTopHint` 是期望状态，原生菜单关闭后 NSWindow 的实际 level 仍可能被 Cocoa 重排，必须在生命周期边界重新断言，但不能用激活窗口的方式修复。
- 动作图标加载期间保持固定占位比旋转几十个加载动画更稳定；后者会持续触发 60–90 行菜单重绘并重新引入 hover 抖动。

### 实现与不变量

- 菜单位于桌宠左边或右边只影响窗口目标坐标，不再改变文字、图标、状态槽
  和箭头的布局方向；根菜单和所有子菜单始终使用 LTR。
- 本轮曾让左侧与远角候选都按整棵菜单树宽度计算；第十九轮实机复验确认，

- 菜单先在目标点朝桌宠方向偏移 18px 的屏幕内位置显示，再用 140ms

- “弹到桌宠左侧”和“把菜单改成 RTL”是两个独立概念。用布局方向控制弹出
  侧会镜像整套视觉语义，正是本轮截图中的错误。
- 本轮曾假设取消 RTL 后必须把最大子菜单宽度纳入左侧根菜单目标；第十九轮
  证明这会制造与子菜单宽度相等的过大间距，应由 Qt 处理子菜单屏幕边界。
- `QMenu.exec()` 虽然启动嵌套事件循环，Qt 属性动画仍可运行；在
  `aboutToShow` 后零延迟启动可确保窗口先位于 transition 起点，同时保留
  现有同步菜单命令与延迟回调生命周期。
- 可见原生 popup 测试不能依赖整个 pytest 进程遗留的 Qt 全局状态。聊天

  降级成 mock，又能让系统边界测试确定清理。
