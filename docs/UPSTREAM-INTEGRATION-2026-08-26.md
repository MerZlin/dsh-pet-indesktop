# 上游合并与新版 UI 收敛记录（2026-08-26）

## 目标

- 合并 `origin/main` 自 `v3.0.0` 之后的功能、平台适配与修复。
- 右键菜单、桌宠设置只维护新版 UI，降低后续同步成本。
- AI 对话保留新版窗口与经典窗口两种可切换实现；两套样式与窗口文件保持独立。
- 所有上游新增功能使用现有新版设计系统重新组织和绘制，不直接复用旧菜单布局。
- 遵循测试先行：先复用或补充失败测试，再实现到全量测试通过。

## 合并策略

1. 在隔离集成分支冻结当前可运行状态。
2. 一次性合并 `origin/main`，保留上游提交关系，避免逐提交重复解决冲突。
3. 优先恢复模型、配置、窗口核心与平台层，再适配新版菜单和设置。
4. 删除旧版菜单和旧版设置的运行时切换入口；保留经典 AI 对话实现。
5. 新增功能通过共享 action/service 接入新版 UI，GUI 线程不执行耗时操作。
6. 运行全量单元测试，随后构建并启动 macOS 验收产物。

## 验收门槛

- 合并后原有与上游测试全部通过。
- 新版菜单可访问所有合并后的用户功能。
- 新版设置可配置相应功能，平台专属项按运行平台显示。
- 新版/经典 AI 对话可切换且样式文件互不覆盖。
- `build/macos/` 下生成可启动应用并实际运行。

## 过程记录

- 合并前基线：沙箱内 135 项通过；2 项本地端口测试因沙箱禁止 `bind(127.0.0.1)` 被拒绝。此前完整环境基线为 137 项通过。
- 合并方式：在隔离集成分支上以保留提交关系的 merge 合入 `origin/main`，冲突按“领域模型/平台核心优先上游、现有新版 UI 优先本地”的边界处理。
- UI 收敛：右键菜单与桌宠设置的运行路径统一到新版实现；旧配置值仅作为迁移输入，不再决定旧菜单/旧设置。AI 对话通过 `chat_ui_style` 在相互独立的现代窗口与经典窗口之间选择。
- 新版菜单接入：看看屏幕、隐藏桌宠、DeepSeek 余额、检查更新与帮助；保留现有动画缩略图异步缓存、快捷启动、彩蛋和现代图标体系。
- 新版设置接入：对话窗口样式选择、视觉模型覆盖、内置/自定义聊天背景、点击音效、点击余额、点击自言自语、余额刷新、Windows 全屏隐藏与直播捕获配置。
- GUI 线程治理：屏幕视觉请求、余额请求和更新检查均在后台线程运行，通过 Qt signal 回到主线程更新气泡；拖拽物理改用纯函数核心，动画菜单继续按需加载代表帧。
- 测试过程：菜单迁移断言先因旧版预期失败，更新为单一新版运行路径后通过；最终在完整权限环境执行 `pytest -q`，结果为 **191 passed, 2 skipped**。
- 构建过程：重新生成并临时签名四个 macOS 应用；主题图片、点击音效及两套独立聊天样式均进入 app bundle。`dsh-pet-standalone-webm-chat.app` 已实际启动，日志确认 91 段动画加载完成并进入 Qt 事件循环。

## 合并后的维护边界

- `pet/context_menu.py` 只分发新版菜单，`context_menu_template=legacy` 只用于兼容旧配置文件。
- 系统托盘和桌宠菜单都只打开 `ModernSettingsDialog`。
- `pet/chat/widgets.py` + `modern_styles.qss` 属于现代 AI 对话；`legacy_widgets.py` + `legacy_styles.qss` 属于经典 AI 对话，两者只共享会话、Provider 与配置模型。
- 后续上游新增 UI 功能应先进入共享 service/action，再用新版菜单和设置组件呈现，避免复制上游旧式 Qt 控件布局。
